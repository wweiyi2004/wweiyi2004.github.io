Embedding 原理图解：从查表到语义检索

魔力充填中 · 约 42 分钟读完

搜索“账号密码忘了该怎么办”，系统却能找到一篇标题叫“通过邮箱重置登录凭证”的文章；两段话没有完全相同的关键词，搜索结果仍然有用。支撑这种能力的一项技术，就是 Embedding，通常译作嵌入或向量表示。

但“把文字变成一串数字”只描述了结果。真正值得追问的是：这些数字最初从哪里来？训练时是谁在修改它们？同一个词在不同句子里为什么会有不同表示？几百个浮点数又怎么用来检索文章？

这篇文章沿着一条完整链路展开：离散符号 → 可训练向量 → 上下文表示 → 句向量 → 相似度 → 检索。我们既看底层矩阵运算，也动手训练一个小模型，最后用真实中文模型跑通检索。读者只需要基本的 Python、向量和矩阵知识；梯度、注意力与对比学习都会在用到时解释。

阅读与复现说明：文中有 8 张原创配图、5 份可下载的完整 Python 示例。示意图中的位置和数值用于解释机制；第十节的相似度图来自实际运行。示例在 Python 3.10.11、PyTorch 2.12.0+cpu、Transformers 4.42.4、Sentence Transformers 5.5.1、NumPy 1.26.4 的现有环境中验证。模型固定到明确 revision，具体浮点数仍可能因计算内核和版本略有差异。

一、先区分：我们说的 Embedding 到底是哪一层？

Embedding 可以表示一个映射过程，也可以表示这个过程产生的向量。在神经网络里，最常见的写法是：

fθ:X→Rd,x↦z.f_\theta:\mathcal X\rightarrow\mathbb R^d,\qquad x\mapsto\mathbf z. fθ​:X→Rd,x↦z.

X\mathcal XX 是输入对象的集合，xxx 可以是一个词、一句话、一张图片或一个商品 ID；ddd 是输出向量的维度；θ\thetaθ 是模型参数。训练的目的是让这个表示保留对目标任务有用的信息。

这里没有承诺“把输入所有信息完整保存”，也没有承诺“不同输入一定对应不同向量”。机器学习语境下的 embedding 不必满足数学中某些严格嵌入定义要求的单射性质。

尤其要区分以下四种常被混用的对象：

名称 输入 输出 是否依赖当前上下文 主要用途
Token embedding 层 一个 token ID 词表矩阵中的一行 单独查表时不依赖 为神经网络提供初始表示
上下文 token 表示 一整段 token 序列 每个位置一个隐藏向量 依赖 理解词义、序列标注、生成等
句子／段落 embedding 一段文本 一个固定维度向量 编码时利用整段文本 相似度、聚类、检索
向量索引／数据库 已经算好的向量及元数据 相近条目及其 ID 本身不学习文本语义 存储、筛选、快速搜索

因此，nn.Embedding 通常只是整个文本编码器的一个组件；向量数据库通常也不会因为“收到文章”就凭空知道它的含义。即使某个数据库产品集成了自动向量化，其背后也要调用具体的 embedding 模型。

本文统一采用以下符号，后面每个矩阵维度都可以对照这里检查：

符号 含义
VVV 词表中的 token 数量
BBB 一个 batch 中的文本数量
LLL 当前 batch 补齐后的序列长度
ddd token 隐藏向量维度
DDD 最终句向量维度，不一定等于 ddd
NNN 候选文档或文档块数量

二、为什么不能直接用编号表示一个词？

2.1 ID 只负责识别，不负责表达关系

假设我们给“猫、狗、飞机”分别编号为 1、2、3。编号 2 并不意味着“狗的语义是猫的两倍”，编号 3 也不意味着飞机比猫更接近狗。编号的排列可以任意交换。

如果直接把这些整数当作连续数值输入一个普通模型，模型可能会接收到人为制造的大小关系与距离关系。我们真正需要的是一种表示，让“哪些性质共享、哪些差异重要”有机会从数据中学出来。

2.2 One-hot 解决了身份问题，却没有学出关系

词表大小为 VVV 时，one-hot 用长度为 VVV 的向量表示某个 ID，只有对应位置是 1：

x猫=[1,0,0],x狗=[0,1,0],x飞机=[0,0,1].\mathbf x_{\text{猫}}=[1,0,0],\qquad \mathbf x_{\text{狗}}=[0,1,0],\qquad \mathbf x_{\text{飞机}}=[0,0,1]. x猫​=[1,0,0],x狗​=[0,1,0],x飞机​=[0,0,1].

任意两个不同的 one-hot 向量内积为 0，欧氏距离为 2\sqrt 22​。所以在这套表示中，“猫与狗”和“猫与飞机”的距离一样大。它准确地区分了身份，却没有表达我们想要的语义结构。

此外，如果 V=50 000V=50\,000V=50000，每个词的显式 one-hot 就有 50 000 维，大部分还是 0。虽然可以使用稀疏存储，但后续神经网络通常更愿意处理较短、可训练的稠密向量。

2.3 稠密向量让不同对象能够共享特征

我们可以给每个 token 分配一个 ddd 维向量，例如 d=128d=128d=128，其中每个坐标都是可学习的浮点数。不同 token 可以在多个方向上接近或分离。

不要急着把第 1 维叫作“动物程度”、第 2 维叫作“可爱程度”。真实模型的语义通常分散在许多维度和方向的组合中。稠密向量提供了表达关系的能力；训练任务决定这种能力最终用来表达什么。 随机初始化的一张向量表不会自动懂中文。

三、Embedding 层的实现：就是查一张可训练的表

3.1 一行对应一个 token

最基础的 embedding 层包含一个参数矩阵：

E∈RV×d.E\in\mathbb R^{V\times d}. E∈RV×d.

第 iii 个 token 的初始向量是 EEE 的第 iii 行：

ei=E[i,:].\mathbf e_i=E[i,:]. ei​=E[i,:].

当输入是一批 token ID，形状为 [B,L][B,L][B,L] 时，查表后的结果就是 [B,L,d][B,L,d][B,L,d]。输出多出来的最后一个维度，正是每个 token 的向量坐标。

这个操作还可以写成矩阵乘法。把 token 的 one-hot 写成行向量 xi\mathbf x_ixi​，就有：

ei=xiE.\mathbf e_i=\mathbf x_iE. ei​=xi​E.

因为 xi\mathbf x_ixi​ 除第 iii 个位置外都是 0，乘法结果只留下 EEE 的第 iii 行。实际框架直接按 ID 索引，避免真的生成巨大的 one-hot。PyTorch 的 nn.Embedding 就提供这种查表行为。PyTorch Embedding 文档

3.3 为什么重复的 ID 会累加梯度？

将所有输入位置记为 ppp，位置 ppp 的 token ID 为 ipi_pip​。因为多个位置可能读取同一行参数，链式法则给出：

∂L∂E[j,:]=∑p:ip=j∂L∂ep.\frac{\partial\mathcal L}{\partial E[j,:]} =\sum_{p:i_p=j}\frac{\partial\mathcal L}{\partial\mathbf e_p}. ∂E[j,:]∂L​=p:ip​=j∑​∂ep​∂L​.

也就是说，参数是共享的；每次使用它产生的梯度，最终都汇总到同一行。示例把所有输出坐标相加，因此每次使用某行，该行的每个坐标都会获得 1 的梯度；使用两次就得到 2。

使用学习率 η=0.1\eta=0.1η=0.1 的普通 SGD 后，ID 3 这一行的每个坐标都减少约 0.2：

E←E−η∂L∂E.E\leftarrow E-\eta\frac{\partial\mathcal L}{\partial E}. E←E−η∂E∂L​.

注意两个边界：这里讨论的是查表路径的梯度；如果词表还被共享给输出分类器，别的计算路径也可能产生梯度。另外，“某行本步梯度为 0”不保证任何优化器都会让它纹丝不动，动量、权重衰减和历史状态也会影响参数更新。本例特意使用没有这些因素的 SGD。

四、训练怎样让向量开始有意义？从 Word2Vec 看起

4.1 “出现在相似上下文中”是一种可利用的信号

如果“猫”和“狗”常出现在“喂养、宠物、喜欢”等相似上下文里，预测上下文的模型有机会学到它们共享的特征。这是分布式词表示的基本出发点。

它不等于“经常相邻的词就是同义词”。“医生”和“医院”经常关联，但不是同义词；“增加”和“减少”可能出现在相似语境里，却有相反含义。词向量反映训练统计关系，不能直接当作逻辑系统。

Word2Vec 的两种经典思路是：CBOW 用上下文预测中心词，Skip-gram 用中心词预测上下文词。下面选后者展开。Word2Vec 原论文

4.3 两张表、一次点积、一项损失

Skip-gram 可以使用两张参数表：中心词表 VinV_{\mathrm{in}}Vin​ 和上下文词表 UoutU_{\mathrm{out}}Uout​。这里的 VinV_{\mathrm{in}}Vin​ 是矩阵名称，与前文表示词表大小的标量 VVV 区分开。

从中心词表取出 vc\mathbf v_cvc​，从上下文表取出候选词的 uj\mathbf u_juj​，点积给出匹配分数：

sj=vc⊤uj.s_j=\mathbf v_c^\top\mathbf u_j. sj​=vc⊤​uj​.

通过 softmax 得到所有上下文候选的分布：

P(o∣c)=exp⁡(vc⊤uo)∑j=1Vexp⁡(vc⊤uj).P(o\mid c)=\frac{\exp(\mathbf v_c^\top\mathbf u_o)} {\sum_{j=1}^{V}\exp(\mathbf v_c^\top\mathbf u_j)}. P(o∣c)=∑j=1V​exp(vc⊤​uj​)exp(vc⊤​uo​)​.

对真实上下文 ooo，负对数似然损失是：

L=−log⁡P(o∣c).\mathcal L=-\log P(o\mid c). L=−logP(o∣c).

如果真实上下文的概率偏低，损失就大。优化器通过梯度改变两张表，让这个上下文相对于其他候选更容易被预测到。

4.4 把“拉近、推远”落实到梯度上

令 pj=P(j∣c)p_j=P(j\mid c)pj​=P(j∣c)，中心向量的梯度可以写成：

∂L∂vc=∑jpjuj−uo.\frac{\partial\mathcal L}{\partial\mathbf v_c} =\sum_jp_j\mathbf u_j-\mathbf u_o. ∂vc​∂L​=j∑​pj​uj​−uo​.

执行梯度下降时，vc\mathbf v_cvc​ 会增加真实上下文方向的贡献，同时减去当前预测分布的加权平均方向。上下文表也随之调整。

这比“模型觉得猫和狗很像，所以把它们放一起”更接近实际发生的事情：模型先努力降低预测损失，词向量中的结构是在大量更新过程中形成的。 猫和狗不必直接构成正样本；相似的上下文预测需求也可能塑造相似的表示。

还要注意：提高点积并不严格等于缩小欧氏距离，向量的长度也会影响点积。“拉近”是直觉描述，真正受到优化约束的是所使用的分数与损失。

4.6 大词表为什么需要负采样？

完整 softmax 每个样本都要对整个词表算分。大词表下，可以改为区分真实词对与采样得到的噪声词对。设正上下文为 ooo，负样本为 n1,…,nKn_1,\ldots,n_Kn1​,…,nK​，一项负采样损失是：

Lneg=−log⁡σ(vc⊤uo)−∑k=1Klog⁡σ(−vc⊤unk).\mathcal L_{\mathrm{neg}} =-\log\sigma(\mathbf v_c^\top\mathbf u_o) -\sum_{k=1}^{K}\log\sigma(-\mathbf v_c^\top\mathbf u_{n_k}). Lneg​=−logσ(vc⊤​uo​)−k=1∑K​logσ(−vc⊤​unk​​).

σ\sigmaσ 是 sigmoid。第一项鼓励真实词对获得较高分数，后面的项抑制采样噪声词对的分数。原始工作研究了按词频的 3/43/43/4 次幂构造采样分布的方法。负采样论文

负采样改变了训练目标，不能把它直接解释成“精确算出了完整 softmax 的概率”。上面的教学代码也没有使用负采样；词表只有 14 个词，完整计算更便于理解。

五、真实文本进入模型前，还要经过 Tokenizer

5.1 字符、词、token 并不是同一个东西

在刚才的教学代码里，我们用空格把“猫 喜欢 吃 鱼”切成词。真实模型一般有自己固定的 tokenizer，可能使用字符、子词或字节片段。英文单词可能被拆成多个子词，中文词语也可能被拆成单字或更长片段。

因此不能简单认为“一万个汉字就等于一万个 token”，也不能在换模型时保留原模型生成的 token ID。ID 17 对应什么，由特定 tokenizer 的词表决定。

Tokenization 通常包含以下工作：文本规范化与切分、子词编码、映射为整数 ID、添加特殊 token，以及按 batch 做 padding。具体步骤取决于模型配置，不应手动猜测。

如果一个模型最多接收 512 个 token，而原文有 2 000 个 token，直接设置 truncation=True 会截掉超过长度限制的部分。被截掉的段落根本没有参与前向计算。

因此，“模型返回了一个向量”不表示“整篇文章都被理解了”。对于长文档，应先设计切块策略，保留标题、段落结构和来源信息，再分别编码；后文会讲如何检查切块是否合理。

六、Transformer 怎样让同一个词获得不同表示？

6.1 查表得到的是起点

“我刚吃了一个苹果”与“苹果发布了新款电脑”里的“苹果”，可能使用相同的 token ID 或相同的 token 片段组合。初始查表向量可以相同，但我们希望最终表示能反映不同语义。

Transformer 通过上下文交互来完成这件事。对于采用绝对位置 embedding 的典型 BERT 式输入，可将初始表示概念性地写为 token、位置以及适用时的 segment 表示之和，再做相应处理：

hi(0)=LayerNorm⁡(etoken,i+eposition,i+esegment,i).\mathbf h_i^{(0)}=\operatorname{LayerNorm} \left(\mathbf e_{\mathrm{token},i}+\mathbf e_{\mathrm{position},i} +\mathbf e_{\mathrm{segment},i}\right). hi(0)​=LayerNorm(etoken,i​+eposition,i​+esegment,i​).

这不是所有 Transformer 的统一输入公式：有的没有 segment embedding，有的通过相对位置机制或 RoPE 让注意力感知位置。理解经典结构后，仍需以实际模型配置为准。BERT 论文

6.2 自注意力把哪些信息混到一起？

先忽略 batch 维度，设当前层输入 H∈RL×dH\in\mathbb R^{L\times d}H∈RL×d。单个注意力头先做三个线性投影：

Q=HWQ,K=HWK,Vattn=HWV.Q=HW_Q,\qquad K=HW_K,\qquad V_{\mathrm{attn}}=HW_V. Q=HWQ​,K=HWK​,Vattn​=HWV​.

注意力计算是：

6.3 语言模型训练目标与检索目标还有一段距离

掩码语言模型学习预测被遮住的 token；自回归语言模型学习预测后续 token。这些任务会让隐藏状态包含有用信息，但不自动保证“取出某个隐藏状态后，用余弦相似度就能做好句子检索”。

检索希望两个独立编码结果的相似度能对应任务相关性，而语言建模并不一定直接优化这个量。这也是句向量模型通常需要额外训练设计的原因。Sentence-BERT 论文

七、怎样把多个 token 向量变成一个句向量？

7.1 Pooling 是序列到固定向量的接口

检索系统一般希望每篇短文或每个文档块对应一个向量。编码器却返回 LLL 个位置的隐藏状态，因此需要 pooling，也就是把序列表示聚合起来。

常见做法包括：取最终层的 [CLS] 位置；对有效位置做平均；按模型约定取最后一个有效 token；或者使用学习得到的加权聚合。后面还可能有投影层，把 ddd 维变成 DDD 维。

这些做法并非可以随意替换。模型训练时使用哪个表示参与损失，推理时就应遵守相同的计算约定。 不能因为平均池化“看起来更公平”，就擅自替换一个经过 CLS 池化训练的模型。

7.3 归一化是长度处理，不是重新理解语义

常见的 L2 归一化为：

八、句向量怎样训练？对比学习把目标写得更直接

8.1 先定义什么算正确配对

一个检索训练样本可以包含：

  • Query：账号密码忘了怎么办？
  • Positive：忘记密码后，通过邮箱验证即可重置。
  • Negative：进入个人资料页面上传新头像。

8.3 温度、难负样本与假负样本

温度减小会放大 logits 之间的差异，也改变梯度尺度和训练关注点。它是需要结合任务选择的超参数，不是越小越好。示例里的 0.1 只用于说明计算，与后面 BGE 模型的具体训练温度无关。

容易负样本可能与问题毫不相干，模型很快就能区分。难负样本则看起来很像，例如“修改密码”和“找回密码”的说明，能迫使模型学习更细的差异。

但难负样本也更容易标错：一篇“邮箱验证重设登录凭证”的文章，可能与已有正样本一样能回答问题。如果把它当负样本强行推开，训练目标就自相矛盾。这叫假负样本问题，可以通过去重、人工抽查、多正样本目标或适当 masking 等方式缓解。

正样本、负样本和任务定义都不可靠时，仅仅堆大模型或增加向量维度，并不能自动修复数据问题。

九、向量生成之后，怎么判断两个对象是否接近？

9.1 三种常见打分方式

对非零向量 a\mathbf aa 和 b\mathbf bb，余弦相似度定义为：

cos⁡(a,b)=a⊤b∥a∥2∥b∥2.\operatorname{cos}(\mathbf a,\mathbf b) =\frac{\mathbf a^\top\mathbf b}{\lVert\mathbf a\rVert_2\lVert\mathbf b\rVert_2}. cos(a,b)=∥a∥2​∥b∥2​a⊤b​.

它衡量方向接近程度，理论取值范围是 [−1,1][-1,1][−1,1]。点积则直接计算 a⊤b\mathbf a^\top\mathbf ba⊤b，同时受方向与长度影响。欧氏距离计算 ∥a−b∥2\lVert\mathbf a-\mathbf b\rVert_2∥a−b∥2​，值越小越近。

如果两边都归一化到单位长度，就有：

∥a^−b^∥22=2−2a^⊤b^=2−2cos⁡(a,b).\lVert\hat{\mathbf a}-\hat{\mathbf b}\rVert_2^2 =2-2\hat{\mathbf a}^\top\hat{\mathbf b} =2-2\operatorname{cos}(\mathbf a,\mathbf b). ∥a^−b^∥22​=2−2a^⊤b^=2−2cos(a,b).

因此，在同一批单位向量上做精确排序时，最大点积、最大余弦和最小欧氏距离给出的顺序一致。若只归一化了一边，或者实际索引使用了量化、近似搜索等手段，就不能直接套用“结果一定完全一致”的结论。

9.2 用一个能手算的例子检查理解

设 a=[1,0]\mathbf a=[1,0]a=[1,0]，b=[0.8,0.6]\mathbf b=[0.8,0.6]b=[0.8,0.6]，c=[0,1]\mathbf c=[0,1]c=[0,1]，它们的长度都是 1。于是：

cos⁡(a,b)=0.8,cos⁡(a,c)=0.\operatorname{cos}(\mathbf a,\mathbf b)=0.8,\qquad \operatorname{cos}(\mathbf a,\mathbf c)=0. cos(a,b)=0.8,cos(a,c)=0.

b\mathbf bb 与 a\mathbf aa 方向更接近。但如果把 c\mathbf cc 改成 [100,1][100,1][100,1]，未经归一化的点积会因长度改变而剧烈变化。这个例子说明：选什么距离，并非无关紧要的接口参数。

9.3 相似度 0.8 不表示“80% 正确”

一个 embedding 分数通常没有经过概率校准。0.8 可能在某种模型上很高，在另一种模型或另一类文本中却很普通。甚至不相关文本也可能获得明显为正的余弦分数。

检索首先依赖相对排序。如果要设置“低于多少就不回答”的阈值，需要用自己的相关／不相关样本校准，并观察精确率、召回率和误拒绝率。更换模型、指令或文档分块方式后，旧阈值也需要重新评估。

十二、从五篇短文到真实知识库：切块、索引、精排与 RAG

12.1 文档切块决定模型到底看见了什么

一篇长文包含多个主题时，整篇压成一个向量可能难以突出某个具体细节。更常见的做法是先按章节或段落切成 chunks，再为每个 chunk 生成向量。

切块过小，容易缺失定义、条件和指代关系；切块过大，容易主题混杂或触发截断。重叠可以保留边界信息，但也会增加存储与重复候选。一个可操作的调试起点是：按完整段落聚合，并尝试每块 256～384 token、少量边界重叠，再用真实问题比较效果。这只是针对本文 512 token 示例模型的起始实验范围，不是通用最佳值。 标题、指令和特殊 token 也会占用输入预算。

例如原文说“这种方法在 batch 很小时效果不好”，如果切块后只留下这一句，却丢了上一段对“这种方法”的定义，再好的模型也很难补回确切指代。可以在块前附上文档标题和章节标题，但要避免把所有导航、页脚和广告都混入正文。

12.2 精确检索与近似检索分别解决什么问题？

示例用矩阵乘法扫描所有文档，对一个查询的主要打分成本约为 O(ND)O(ND)O(ND)。小语料上直接精确搜索很容易调试，也适合成为评估近似索引的基准。

当 NNN 很大时，可以使用 HNSW、IVF 等近似最近邻方法，在速度、内存和召回之间取舍。这里改变的是查找过程，而不是文本编码模型的语义能力。近似索引可能漏掉本来应该入选的候选，因此应单独测量它相对于精确向量搜索的召回。Faiss 索引说明

再估算一次容量：100 万条 768 维 float32 向量需要 106×768×4=3.07210^6\times768\times4=3.072106×768×4=3.072 GB，约 2.86 GiB。这仅是原始向量，不包含索引结构、ID、文本、元数据、数据库副本等开销。

12.3 为什么常常还需要关键词检索和 reranker？

Embedding 擅长处理表达方式不同但相关的文本；对精确编号、函数名、错误码、日期或细小的否定关系，单纯的语义向量可能不够。例如 ERR_1042 与 ERR_1043 只差一个字符，含义却可能完全不同。

可以把关键词检索与向量检索组合成混合检索，再通过排名融合或后续精排选择候选。不要直接把 BM25 分数与余弦分数随意相加，它们不在同一量纲上；需要校准、权重实验或基于排名的融合方法。

Reranker 通常把 query 和候选文档一起输入 cross-encoder，让两边 token 直接交互，输出相关性分数。它适合对少量已召回候选重新排序，因为每个 query-document 对都要计算一次，难以像双编码器那样把所有文档向量一次算好反复复用。Retrieve & Re-Rank 文档

12.4 RAG 怎样接上这条链路？

典型流程是：文档预处理与切块，计算并存储文档向量；收到问题后计算查询向量，检索相关块；可选地精排和去重；把检索到的原文内容与来源放入生成模型的上下文，让它依据这些材料作答。

这里传给生成模型的通常是被找回的文本，而不是那一串 512 维浮点数。Embedding 模型负责表示，索引负责找候选，生成模型负责结合问题和材料生成回答。某一个环节出错，最终答案都可能出错。

向量命中也不等于事实核验：一段过期材料可以与问题高度相关，一段错误解释也可能具有很高相似度。检索系统还需要日期、版本、来源和访问权限等元数据，才能把“相似”进一步约束为“适合当前用户使用”。

十三、怎样证明一个 Embedding 系统真的好用？

13.1 准备一小份可信的评估集

先从实际用户问题中抽取一批查询，为每个查询标注哪些文档块能回答问题。包含常见问题，也包含歧义、精确编号、否定表达、超长问题以及知识库没有答案的问题。

评估集不应与训练或调参数据完全重合。比较模型、指令与切块方案时，应尽量固定其他因素，否则很难知道提升来自哪里。

13.2 用指标定位问题所在

指标 它回答的问题 使用时的注意点
Recall@k 标注的相关条目有多少出现在前 k 个结果中？ 需要知道每个 query 的相关集合
Hit@k 前 k 个结果里是否至少命中一个相关条目？ 不等于一般定义下的 Recall@k
MRR 第一个相关结果排得多靠前？ 无命中查询的倒数排名通常记 0
nDCG@k 高相关文档是否排在更前面？ 可以利用分级相关性标签
延迟与吞吐 用户等待多久，单位时间处理多少请求？ 分开统计编码、检索、精排耗时

对单个 query，若相关集合为 RRR，返回的前 kkk 个条目为 TkT_kTk​，则：

Recall@k⁡=∣R∩Tk∣∣R∣,∣R∣>0.\operatorname{Recall@k}=\frac{|R\cap T_k|}{|R|},\qquad |R|>0. Recall@k=∣R∣∣R∩Tk​∣​,∣R∣>0.

有 3 篇相关文档，而前 5 个结果命中其中 2 篇时，Recall@5 为 2/32/32/3，Hit@5 为 1。若每个问题恰好只有一篇相关文档，两者才会对该问题一致。对于没有相关文档的查询，应另行评估拒答与误检，不能直接在这个公式中除以 0。

还要区分两类召回：任务召回比较返回结果与人工标注的相关文档；ANN 索引召回比较近似检索与精确向量搜索的结果。前者检验整个表示与检索方案是否有用，后者检验索引是否忠实地找到向量邻居。

13.3 按症状排查，比盲目换模型更有效

症状 优先检查
同一段话重复编码差异很大 是否 eval()；模型版本、输入预处理、精度与设备是否一致
短句能搜，长文细节搜不到 是否截断；切块是否丢失上下文；标题有没有保留
返回的文档与分数对不上 向量行号、chunk ID 与原文映射是否错位
换模型后效果突然下降 查询和文档是否使用不同模型／不同维度；旧索引是否重建
否定句、型号、错误码总混淆 是否需要关键词约束、混合检索或精排
几乎所有分数都很高 阈值是否照搬；输入是否重复；模型分数分布是否本来如此
近似检索比精确检索差很多 距离类型、归一化与索引参数是否匹配
小样本好、上线后差 评估集是否覆盖真实问题，语料是否存在领域差异与过期内容

十四、几个值得反复澄清的问题

14.1 每个维度能不能直接解释成一个概念？

通常不能。一个有用的思考实验是：若将所有向量乘以同一个正交矩阵 RRR，满足 R⊤R=IR^\top R=IR⊤R=I，则点积和长度保持不变，相似度排序也保持不变。但每个坐标轴已经旋转了。

既然坐标旋转后功能不变，就没有理由断言某个固定编号的维度必然对应唯一的人类概念。可以研究方向、子空间与探针，但那需要额外实验，不能凭看几组数字命名坐标。

14.2 维度越高，一定越好吗？

不一定。维度增大可能提高表示容量，也增加存储、传输和搜索成本。训练数据、目标、领域适配和输入处理都可能比维度更重要。

同样，不能把一个 768 维向量随手切成前 256 维，就宣称获得等价的小向量模型。只有模型明确支持可变维度输出，或者使用了经过训练与验证的降维方案，才应按相应方法操作。

14.3 二维散点图能不能证明模型理解了语义？

不能。PCA、t-SNE、UMAP 等把高维结果压到二维时，都会改变或舍弃一部分结构。可视化适合帮助发现模式和异常，但“图上分成几团”不等于检索质量好，也不应把二维图里的距离直接当作原空间距离。

本文前面的点位图因此明确标成示意图；实战部分直接展示真实高维向量计算得到的分数矩阵，避免把手绘点位当作模型实验。

14.4 Embedding 是压缩、加密还是摘要？

它是为任务学习的表示，可能丢失大量原文细节，通常不能像无损压缩那样按固定算法恢复原文。它也不是自然语言摘要，向量中的每个数不对应摘要里的一句话。

更不能把它当作安全加密。不要因为数据库里存的是浮点数，就忽略访问控制或认为数据可以随意公开。这里最实用的判断是：向量属于从原始数据计算出的派生数据，应结合原文的使用边界来管理。

14.5 能不能用聊天模型的隐藏状态直接做检索？

技术上可以提取隐藏状态，但必须确定取哪一层、哪个位置、怎样 pooling，以及查询与文档如何输入。生成效果好不代表这些向量已经针对检索校准，质量应以实际评估为准。

如果一个模型专门提供 embedding 能力，就应使用它定义的编码流程；不能把任意接口返回的 token logits、注意力权重或 KV cache 当成可互换的句向量。

14.6 从零训练、微调、调用现成模型，分别适合什么时候？

学习底层机制时，从零训练小模型很有价值；搭建一般检索原型时，先使用任务合适的现成编码器，能更快暴露数据与切块问题；当领域术语、问题表达或业务相关性与预训练任务差异明显时，再考虑用可靠配对数据微调。

微调前先保存基线评估结果。否则训练损失下降了，却无法判断原本能处理的问题是否退化，也无法知道性能提升是否值得额外维护成本。

十五、把完整过程串起来

现在重新看“账号密码忘了该怎么办？”这句话，系统可以依次完成这些实际操作：

  1. 按模型要求补上查询指令，交给配套 tokenizer。
  2. 获得整数 ID、特殊 token、padding 与 attention mask。
  3. 通过可训练词表查出初始 token 向量，并按架构加入位置信息。
  4. 经过多层 Transformer，让各位置结合上下文更新隐藏状态。
  5. 按训练约定取 CLS、masked mean 或其他聚合结果，得到固定维度向量。
  6. 按模型约定投影或归一化，用匹配的打分方式与文档向量比较。
  7. 取回高分条目的原文，必要时精排，再用于搜索展示或 RAG 回答。

而这整条链之所以可能有用，是因为更早的训练阶段已经用语料、配对关系、损失函数和梯度更新，塑造了编码器的参数。数字的计算过程由网络结构决定，数字所保留的关系由训练任务与数据塑造，最终有没有用则要由真实任务检验。

如果只做三次练习，建议先运行 01_lookup.py 看梯度如何回到词表，再修改 02_skipgram.py 的语料观察邻居变化，最后在 04_search.py 里加入自己博客的段落和真实查询。把输出形状、分数与原文逐项对上，Embedding 就会从一个名词变成可检查的计算过程。
