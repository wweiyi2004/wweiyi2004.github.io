前言与背景

做图像匹配的时候，我们通常要干两件事：先在两张照片里找到“能反复认出来的关键位置”，再给每个位置算出一串特征向量，方便两张图拿去比对。

传统做法是把“找点”和“描述点”拆成两步来做；但换到深度学习里，马上就会遇到一个很头疼的问题：真实照片里的兴趣点太难标了——一张街景图里到底哪几个像素算“标准兴趣点”，靠人工很难大量、统一地标出来。

SuperPoint 的想法很直接：它把兴趣点检测和描述子生成放进同一个全卷积网络里一起学。为了绕开“人工标点难”的问题，它分步来解决：

  1. 先拿程序画出来的简单几何图形（这些图形的角点坐标程序天生就知道）训练一个基础检测器；
  2. 再拿这个检测器去“多角度观察”真实照片，把多次结果对齐汇总，自动造出一批真实照片的伪标签；
  3. 最后利用已知的图像几何变换关系，同时训练检测和描述两个分支。

在本文中，我们试着把 SuperPoint 的训练流程、推理过程一步步拆开讲透，再结合我本地跑的从头训练、大角度微调、通道压缩以及 HPatches 实测结果，看看它到底表现如何、边界在哪里。

1. 训练流程详解

SuperPoint 的训练大体分成三个阶段：

  1. 第一阶段：在合成几何图形上学会“找点”（得到 MagicPoint）；
  2. 第二阶段：用 MagicPoint 给真实照片自动生成伪标签（单应适应）；
  3. 第三阶段：在真实图像对上，联合训练检测和描述两个任务（得到 SuperPoint）。

在往下看之前，我们要先在脑子里把这两个任务分清楚：

  • 检测任务：回答“图片里哪些位置应该被选成兴趣点？”（兴趣点 Interest Point 就是那种足够醒目、换张图也能再次找到的位置。）
  • 描述任务：回答“两张图里，哪些位置的描述子应该长得像？”（描述子 Descriptor 就是用来刻画某个点周围长什么样的一串数值向量。）

这两个任务用的监督信号完全不同，但在网络里共用同一个编码器，最后一起优化。

1.1 整体训练一览

先把三个阶段的输入输出放在一张表里，方便对照：

阶段 输入 主要操作 输出
合成预训练 合成几何图像 + 已知点标签 训练编码器与检测头 MagicPoint
单应适应 未标注真实图像 + 基础检测器 多视图检测、对齐、汇总 真实图像兴趣点伪标签
联合训练 真实图像 + 伪标签 + 已知单应变换 同时优化检测与描述损失 SuperPoint

注意：单应适应（也就是让检测器从多个变换视角反复看同一张图，再把结果对齐汇总）主要是用来“造训练标签”的，推理时不会跑它，训练时也不需要每次迭代都重跑。另外，伪标签毕竟是 MagicPoint 自己预测出来的，并不保证 100% 正确。

1.2 第一阶段：在合成图像上预训练 MagicPoint

第一阶段的思路非常直观：既然真实照片不好标角点，我们就先用代码画几何图形。

第一步：生成合成几何图像

程序在画图时，天然就知道每个顶点的精确坐标。常见的合成图形包括：

  • 三角形、四边形；
  • 棋盘格、规则网格；
  • 线段及其端点；
  • 星形；
  • 立方体线框。

比如画一个三角形，程序画完的同时就已经拿到了三个顶点的坐标，于是可以直接得到一对训练数据：

text
合成图像 I + 已知兴趣点坐标 Y

我们还可以对画好的图形做几何变换，同时把坐标 Y 一起跟着变，这样样本就更丰富了。（原论文里的合成图是边训练边动态生成的，不需要提前全部存到硬盘里。）

第二步：把点坐标转成 65 类分类标签

SuperPoint 的编码器里包含三次最大池化（中间穿插卷积），经过它之后，特征图的长宽会缩小到原图的八分之一：

text
原图：H × W
粗网格：H/8 × W/8

你可以把粗网格上的每一个格子，看作原图里一块互不重叠的 8×8 像素小块。检测头要做的事情，就是给每一个 8×8 小块做一次 65 分类：

  • 前 64 类：对应这个 8×8 小块里的 64 个像素位置；
  • 第 65 类：表示这块区域里压根没有兴趣点（论文里叫 dustbin，可以理解成“垃圾桶/背景类”）。

所以每个小块的标签规则很简单：

text
区域内有兴趣点：标签 = 兴趣点在这个 8×8 区域里的像素位置编号
区域内没有兴趣点：标签 = dustbin

如果碰巧同一个 8×8 小块里落进了好几个标注点，原论文的做法是随机选一个当训练标签。

注意：训练时每个 8×8 区域只给一个分类标签，并不代表推理阶段解码后，每个区域就只能输出一个点。

第三步：输入网络，得到预测

第一阶段只用共享编码器 + 检测头（描述头这时还不上场）：

text
合成图像 → 共享 CNN 编码器 → 检测头 → 每个粗网格的 65 类预测

检测头输出的张量形状是：

text
[B, 65, H/8, W/8]

其中 B 是批次大小，H、W 是原图高宽，65 就是上面说的 65 个类别。

第四步：算损失、更新参数，得到 MagicPoint

接下来把每个区域的 65 类预测和真实标签做交叉熵损失（有兴趣点就拉高对应像素位置的概率，没兴趣点就拉高 dustbin 的概率），然后走标准的反向传播流程：

text
清空梯度 → 反向传播 → 优化器更新编码器与检测头参数

训完之后，我们就拿到了基础检测器 MagicPoint。它已经能认出不少角点和交点了，但还有两个明显的短板：

  1. 合成图形和真实照片差距太大（存在分布差异）；
  2. 它现在只会找点，还不会生成描述子。

所以接下来，我们要想办法把它搬到真实照片上。

1.3 第二阶段：通过单应适应给真实图像造伪标签

这一阶段的核心目标只有一句话：用刚才训好的 MagicPoint，给没有人工标注的真实照片自动生成尽量靠谱的兴趣点标签。（注意：这整个过程里检测器的权重是冻住的，只做推理和汇总，不更新参数。）

下面我们拿一张建筑照片 III（比如有很多窗户角、墙面交点，但没有任何标注）为例，看看具体怎么操作：

第一步：给原图做一堆已知的单应变换

我们随机采样 KKK 个单应矩阵 H1,H2,…,HKH_1, H_2, \ldots, H_KH1​,H2​,…,HK​，分别把原图 III 变换成 KKK 张不同视角的图：

Ik=warp⁡(I,Hk)I_k = \operatorname{warp}(I, H_k) Ik​=warp(I,Hk​)

这些变换里可以包含平移、缩放、平面内旋转和透视形变。因为变换矩阵是我们自己生成的，所以原图和每张变换图之间的像素对应关系是完全已知的。

第二步：每张变换图都跑一遍 MagicPoint

把这 KKK 张变换后的图依次送进 MagicPoint，各自得到一张兴趣点分数图：

text
变换图像 1 → MagicPoint → 分数图 1
变换图像 2 → MagicPoint → 分数图 2
变换图像 3 → MagicPoint → 分数图 3
……

为什么要多看这么多遍？因为同一个窗户角，换个角度、缩个比例，检测器给出的响应可能忽高忽低。多变换几次再汇总，相当于听取多个视角的“集体投票”，比只信单次预测稳得多。

第三步：把分数图映回原图坐标系

不同变换图里同一个 (x, y) 坐标对应的早就不是原图里的同一个位置了，所以绝对不能直接把这些分数图直接相加。

我们要用每次变换的逆矩阵，把每张分数图都投影回原图坐标系下：

text
变换图中的预测 → 按已知逆变换映回原图 → 同一物理结构的分数落回同一个位置

（注意这里映回去的是检测分数图，跟描述子没关系。）

第四步：只按“有效观测”求平均

对齐之后，就能把同一个位置上的分数做平均了。但这里有个很容易踩的坑——必须排除变换后移出画面、或者靠边界填充出来的无效区域。

举个例子，假设某个角点在三次变换里的观测结果是：

text
第 1 次：0.9
第 2 次：0.8
第 3 次：移出画面，没观测到

那么它的平均分数应该是：

0.9+0.82=0.85\frac{0.9 + 0.8}{2} = 0.85 20.9+0.8​=0.85

而不是把第 3 次当成 0 再除以 3。**注意：没观测到，不等于检测器觉得这里不是兴趣点。**写代码时，通常是用一张有效区域掩码（mask）记下每个位置到底被有效看到了几次，再拿它当分母。

第五步：从汇总分数图里挑出点标签

汇总完得到的还是一张连续的分数图，我们再做两步后处理，就能抽出最终的点坐标：

text
汇总分数图 → 阈值筛选 → 非极大值抑制（NMS） → 保留兴趣点坐标

这样我们就拿到了真实图像 III 和对应的兴趣点伪标签 YYY。（叫“伪标签”是因为它来自模型预测而不是人工真值；多视图汇总能压住一部分随机波动，但没法根除系统性错误。）

第六步（可选）：迭代几轮，让标签越来越好

拿第一轮伪标签训出一个适应了真实照片的新检测器之后，我们还可以用这个新检测器再跑一遍单应适应，生成质量更高的第二轮伪标签。原论文里就用了这种迭代套娃的方式：

text
MagicPoint D₀
      ↓ 对真实图像执行单应适应
第一轮伪标签 Y₀
      ↓ 用图像 I 和标签 Y₀ 训练
新检测器 D₁
      ↓ 再对真实图像执行单应适应
第二轮伪标签 Y₁
      ↓ 用图像 I 和标签 Y₁ 继续训练
新检测器 D₂

1.4 第三阶段：联合训练检测头与描述头

现在我们手里已经有了真实图像 III 和它的兴趣点伪标签 YYY。接下来进入最核心的第三阶段：让网络在真实图像上同时学会找点和算描述子。

我们顺着一个训练样本走一遍完整过程：

第一步：采样单应变换，造出一对图像

从训练集取出 (I,Y)(I, Y)(I,Y) 后，随机生成一个单应矩阵 HHH，把图像和点坐标一起变换过去：

I′=warp⁡(I,H),Y′=warpPoints⁡(Y,H)I' = \operatorname{warp}(I, H), \qquad Y' = \operatorname{warpPoints}(Y, H) I′=warp(I,H),Y′=warpPoints(Y,H)

（注意：标签是离散的点坐标，要直接对坐标做几何变换，不能把标签画成图去做普通像素插值；变出画面边界的点也要及时删掉。）

再加上亮度变化、噪声、运动模糊等数据增强，这一对样本就准备好了：手里同时有原图 III、变换图 I′I'I′、各自的检测标签 YYY 和 Y′Y'Y′，以及它们之间已知的几何关系 HHH。

第二步：两张图经过同一套网络参数

把 III 和 I′I'I′ 分别送进同一个 SuperPoint 网络（注意不是两个独立的网络，而是共用同一套编码器、检测头和描述头权重）：

text
I  → SuperPoint → 检测输出 X  + 粗描述图 D
I′ → SuperPoint → 检测输出 X′ + 粗描述图 D′

拿原论文的训练尺寸 240×320 举例，经过 8 倍下采样后，粗网格尺寸就是 30×40，对应的输出张量形状为：

text
检测输出：[B, 65, 30, 40]
粗描述图：[B, 256, 30, 40]

第三步：分别算两张图的检测损失

先把 YYY 和 Y′Y'Y′ 都转成每个 8×8 区域一个 65 类标签的格式，然后分别监督两张图的检测输出：

Ldet=Lp(X,Y)+Lp(X′,Y′)L_{\mathrm{det}} = L_p(X, Y) + L_p(X', Y') Ldet​=Lp​(X,Y)+Lp​(X′,Y′)

可以看到，检测分支并不是只要求两张图输出保持一致，而是两边各自拿对应的标签去监督——既教网络原图哪里该有点，也教它变换后的图哪里该有点。

第四步：用单应矩阵 HHH 找出描述子的“正负对应”

描述头要学的是“同一处物理位置的特征要像，不同位置的特征要不像”。那怎么知道两张图里哪两个格子对应同一个位置？这时候前面保存的单应矩阵 HHH 就派上用场了。

设原图里某个粗描述网格中心对应的像素坐标是 ppp，用 HHH 把它投影到另一张图里：

p′=π(Hp~)p' = \pi(H\tilde{p}) p′=π(Hp~​)

（其中 p~\tilde{p}p~​ 是齐次坐标，π\piπ 表示除以最后一个坐标恢复成二维坐标。）

接着算一算 p′p'p′ 和第二张图里所有粗网格中心的像素距离：

  • 距离够近（论文用的阈值是 8 像素以内）：算正对应；
  • 距离较远：算负对应。

注意一个关键细节：原论文的描述损失是直接作用在两张粗描述图的所有网格单元对上的，并不是先做 NMS 挑出少数兴趣点，再只针对那几个点算描述损失。

第五步：计算描述损失（带间隔的 Hinge Loss）

取出任意一对归一化后的描述向量 ddd 和 d′d'd′，用内积 q=d⊤d′q = d^\top d'q=d⊤d′ 衡量它们的相似度。我们希望正对应越像越好，负对应别太像。

论文用的是带正负间隔（margin）的 Hinge Loss：

  • 正对应损失：ℓpos=max⁡(0,mp−d⊤d′)\ell_{\mathrm{pos}} = \max(0, m_p - d^\top d')ℓpos​=max(0,mp​−d⊤d′)
  • 负对应损失：ℓneg=max⁡(0,d⊤d′−mn)\ell_{\mathrm{neg}} = \max(0, d^\top d' - m_n)ℓneg​=max(0,d⊤d′−mn​)

其中 mpm_pmp​ 是正对应要求达到的相似度下限，mnm_nmn​ 是负对应允许的相似度上限。用大白话理解就是：

text
正对应：相似度还不够高 → 扣分（产生损失）；已经够像了 → 不再管它
负对应：相似度太高了   → 扣分（产生损失）；已经够不像了 → 不再管它

因为一张图里“不是同一个位置”的负样本比正样本多得多，为了不让大量负样本把梯度带偏，论文还专门给正对应项乘了一个较大的权重 λd\lambda_dλd​。

第六步：合并总损失，反向传播

把两份检测损失和描述损失加在一起，就得到总损失：

L=Lp(X,Y)+Lp(X′,Y′)+λLd(D,D′,S)L = L_p(X, Y) + L_p(X', Y') + \lambda L_d(D, D', S) L=Lp​(X,Y)+Lp​(X′,Y′)+λLd​(D,D′,S)

其中 SSS 是刚才由单应关系算出来的描述对应标签，λ\lambdaλ 用来平衡检测和描述两个任务的量级。

反向传播时，梯度会兵分两路往回传：

text
检测损失 ─┬─ 更新检测头
          └─ 更新共享编码器

描述损失 ─┬─ 更新描述头
          └─ 更新共享编码器

这样一来，共享编码器就能同时收到两份反馈：既知道什么样的局部结构好找点，也知道提什么样的特征更方便后续做区分。

1.5 一次联合训练迭代的完整清单

把上面的步骤串起来，一次训练迭代其实就是下面这 13 步（注意伪标签 YYY 提前算好了，直接读就行）：

text
1. 读取真实图像 I 和伪标签 Y
2. 随机采样单应矩阵 H
3. 生成变换图像 I′
4. 同步变换兴趣点坐标，得到 Y′
5. 根据 H 构造粗描述网格之间的对应标签 S
6. 将 I 和 I′ 输入同一个 SuperPoint 网络
7. 得到检测输出 X、X′ 和描述图 D、D′
8. 计算原图检测损失
9. 计算变换图检测损失
10. 计算描述损失
11. 加权合并总损失
12. 清空梯度 → 反向传播 → 优化器更新
13. 进入下一批训练数据

1.7 训练部分最容易搞混的三个问题

总结一下训练阶段，有三个概念最容易绕晕：

  1. “自监督”不等于“没标签”：SuperPoint 训练时全程都有明确的监督信号（合成图的程序坐标、真实图的单应伪标签、图像对之间的单应对应关系），它省掉的只是“大量人工逐张标点”的苦力活。
  2. 检测伪标签 ≠ 描述对应标签：检测伪标签回答“这里该不该有点”，描述对应标签回答“这两处特征该不该像”，两者的来源和用途完全分开。
  3. 单应变换在两个阶段干的活不一样：在单应适应阶段，它用来给同一张图造多视角、汇总伪标签；在联合训练阶段，它用来造训练图像对，并直接给出描述子的正负对应关系。

2. 推理流程详解

刚刚已经把复杂的训练看完了，现在来看看实际推理。好消息是，推理阶段比训练简单得多——先给它定个位：

SuperPoint 本质上是一个“单张图的局部特征提取器”：给它一张图，它吐出兴趣点坐标、检测分数和对应的 256 维描述子。

它本身不负责做两张图的匹配。真要匹配两张图，得分别跑一遍 SuperPoint，再拿描述子去匹配和做几何验证。

我们先用一张表把训练和推理的差别划清：

项目 训练阶段 推理阶段
输入 已知几何关系的图像对 单张图像
检测标签 / 伪标签 需要 不需要
单应关系 用来造样本和算描述监督 不需要
损失计算与参数更新 需要 不需要
主要结果 学到网络参数 输出关键点、分数与描述子

2.1 输入是什么？

推理时只需要喂给网络一张灰度图，典型张量形状是 [B, 1, H, W]（单张推理时 B=1，1 表示单通道灰度），比如 [1, 1, 480, 640]。

如果手头是普通 RGB 照片，先转灰度再按要求做归一化就行。因为编码器会做 8 倍下采样，实际使用时通常要求 H 和 W 能被 8 整除（不行就填充或裁剪一下）。另外，SuperPoint 是全卷积网络，并不要求死卡某一个固定输入尺寸。

推理时不需要第二张图、不需要标签、不需要单应矩阵，更不需要重新跑单应适应。

2.2 一步步看推理怎么跑

还是拿一张 480×640 的建筑照片举例，推理一共就 5 步：

第一步：共享编码器提特征

text
输入灰度图 [1, 1, 480, 640]
        ↓ 卷积、激活、三次最大池化
共享特征图（空间尺寸 60×80）

注意，经过三次池化虽然长宽缩成了 60×80，但多通道里存的是网络学出来的结构特征，不是简单把原图缩小的模糊缩略图。

第二步：检测头解码出原图尺寸的分数图

检测头输出的形状是 [1, 65, 60, 80]（和训练时完全一样：每个粗网格预测 64 个像素位置 + 1 个 dustbin）。接下来按下面四步解码回原图大小：

text
65 通道输出
    ↓ 对 65 类做 Softmax
    ↓ 扔掉 dustbin 通道（注意不重新归一化）
    ↓ 把剩下的 64 个通道重排成 8×8 的像素块
480×640 的兴趣点分数图

这样一来，原图上每一个像素就都有了一个检测分数。

第三步：后处理筛选出最终关键点

对这张 480×640 的分数图做一轮清洗：

  • NMS（非极大值抑制）：同一块角点附近只留响应最强的那个，避免扎堆；
  • 阈值筛选：分数太低的直接丢掉；
  • 去边界：贴着图像边缘的点通常不好用，顺手剔除；
  • 可选 Top-K：如果点数太多，按分数从高到低截断。

最后得到 N 个关键点（N 不固定，取决于图像内容和阈值设置）：

text
关键点坐标：[N, 2]
关键点分数：[N]

第四步：描述头输出粗描述图

和检测头并行，描述头直接输出 [1, 256, 60, 80]。你可以把它看成一张 60×80 的网格地图，每个格子里塞着一个 256 维的向量。

第五步：按关键点位置插值取描述子

现在有个小问题：关键点坐标在 480×640 的原图坐标系里，而描述向量还躺在 60×80 的粗网格上，两边还没对上号。

做法也很直接——对刚才保留下来的 N 个关键点逐个处理：

  1. 把原图坐标换算到 60×80 粗描述图里的对应位置；
  2. 用插值（原论文用的是双三次插值）读出该位置的 256 维向量；
  3. 做一次 L2 归一化。

这样就拿到了 [N, 256] 的描述子。（实战小技巧：完全没必要真的把整个 480×640×256 的稠密描述图全插值算出来，只在挑出来的 N 个点位置上采样就行，能省不少算力和显存。）

2.3 最终输出与后续匹配

推理结束后，我们拿到下面三样东西：

输出 常见形状 含义
关键点坐标 N×2 每个点在原图里的坐标，通常是 (x, y)
检测分数 N 每个点的检测响应强度
描述子 N×256 用来和其他图像做特征比对的向量

比如第 17 个关键点长这样：

text
坐标：(120, 80)
分数：0.92
描述子：[0.03, -0.08, ..., 0.11]（共 256 维）

（不同代码库里描述子有时会存成 256×N，接接口时记得看一眼形状。）

注意：检测分数高，不代表这个点一定能匹配对。 比如一整面一模一样的玻璃幕墙，每个窗角检测分数都很高，但因为长得太像，照样容易配错。

两张图要真正完成匹配，还得在 SuperPoint 后面接上匹配器和几何验证：

text
图像 A → SuperPoint → 点、分数、描述子
                              ↕ 描述子匹配
图像 B → SuperPoint → 点、分数、描述子
                              ↓
                        候选对应关系
                              ↓
                   RANSAC 等几何验证
                              ↓
                        保留可靠匹配

2.4 SuperPoint 的优缺点与适用场景

搞清楚了原理，我们顺手盘点一下它的长处和短板。

主要优点：

  1. 整图共享计算，速度快：不用先抠一堆图块再逐个跑 CNN，整张图过一遍共享编码器就齐活。（原论文在 Titan X、480×640 条件下报过约 70 FPS，不过换硬件和实现后速度肯定不同，别直接套用。）
  2. 检测与描述一起学：两个分支共用主干并联合优化，比“各干各的”复用了更多底层表示。
  3. 不靠人工大量标点：靠合成图 + 单应适应 + 几何对应把训练链路串起来，数据成本低很多。
  4. 对常见成像变化有一定抗性：训练里加了几何和光度增强，在 HPatches 上对常规视角、亮度、轻微模糊表现不错（但不是对所有极端变化都稳）。

主要短板：

局限 具体表现
低纹理区域抓瞎 大片白墙、天空里本来就没什么稳定可区分的局部特征
重复纹理容易配错 一模一样的窗格、砖墙、栅栏很容易让描述子混淆
极端变化依然吃力 大角度旋转、剧烈缩放、极端透视或严重模糊时效果会掉得很快
下采样会损失细节 8 倍下采样后靠通道重排和插值恢复，空间信息还是会有一定损耗
存在训练域偏差 在自然图像上训出来的权重，直接拿去跑医学、红外图未必好用
不是端到端完整匹配系统 后面必须自己配匹配器和 RANSAC 等几何验证模块

比如原论文里就专门展示过：遇到训练中很少见到的极端平面内旋转时，SuperPoint 会直接翻车；另外，单应变换本身只能模拟平面投影，没法完全覆盖真实三维场景里的视差、遮挡和新生区域（当然，这不意味着它只能用于平面图，只是说明它的训练分布是有边界的）。

适合哪些场景？

  • 比较适合：同一场景/物体在不同视角下拍的、有一定重叠和纹理的照片（比如建筑、室内照片、视频相邻帧），常用来做图像拼接/配准、视觉里程计/SLAM、三维重建（SfM）和相机定位的特征前端。
  • 需要谨慎评估：大面积白墙或高度重复纹理、严重运动模糊/过曝/强噪声、视角跨度极大或遮挡严重、布料/生物组织这类大非刚性形变，以及红外/显微/医学等特殊领域图像。遇到这些情况，最好先在自己数据上实测，必要时微调或重训。

3.2 先对齐几个指标的口径

前面我们区分了“找点”和“描述点”，看实验数字时也要把找到点、匹配对、几何算准三件事分开：

指标 回答的问题 本节的计算口径
检测精确率、召回率 合成图形上的角点找得准不准、全不全？ 在 3 像素内和已知角点做一对一匹配
检测重复率 图像变换后，同一个位置还能不能再找到？ 在共同可见区域内，统计 3 像素范围内重复检出的比例
匹配正确率 描述子配出来的点对里，有多少是真的对的？ 用真实/已知单应矩阵投影，前向重投影误差不超过 3 像素的比例
单应成功率@3px 算出来的单应矩阵准不准？ 估计矩阵和真实矩阵把图像四个角投影过去，四角平均误差不超过 3 像素
RANSAC 内点数 有多少候选点对支持当前算出的矩阵？ 只衡量几何一致性，不等于真实正确的匹配数

注意两个容易误读的口径：

  1. 下面的“匹配正确率”是先给每对图算自己的比例，再对所有图像对取平均（HPatches 里没配出点的图像对按 0 算）。也就是说，一张简单图配出 500 对、一张难题只配出 10 对，两者在平均值里权重是一样的，这和“把全部正确数加起来除以全部候选数”不是一个算法。
  2. RANSAC 返回了一个单应矩阵，不等于它算对了。后面从头训练的初步检查只看“有没有返回矩阵”，而大角度微调和 HPatches 才是按“四角误差是否 ≤ 3 像素”判定成功，两者不能直接横向拿来比。

  3. 60° 还是没救回来：单应成功率依然是 0%；
  4. 小角度付出了代价：10° 组的匹配正确率从 87.08% 掉到 83.21%，单应成功率从 96.88% 掉到 92.19%；
  5. 匹配正确率和单应成功率不总是同涨同跌：透视组里匹配正确率降了一点，单应成功率反而从 87.50% 升到了 95.31%，说明最终几何估计还受正确点数量和空间分布的影响。

（同样注一句：这 64 张图虽然和本轮训练/选模分开了，但大来源还是最初的 COCO 验证划分，不能当成完全没接触过的外部测试集。）

那这波改善到底主要发生在网络的哪一块？ 我做了个“固定关键点、逐个替换模块”的小诊断。先看微调前后各模块参数的 L2 相对变化：

模块 参数相对变化
编码器 0.324%
检测头 0.204%
描述头 7.362%

在 12 张选模图、固定原模型关键点的 45° 测试里：原模型匹配正确率是 13.55%；如果只把描述头换成微调后的，正确率立刻涨到 19.61%；如果只换编码器，则只有 14.45%。这说明本轮改善主要出在描述分支——大旋转时很多时候“点其实还找得到，主要是描述子转过头就认不出来了”（当然这只是小样本局部诊断，不能一概而论说所有场景都只怪描述头）。

3.5 保留 75% 通道做压缩，模型还能不能用？

接下来试试模型瘦身。这里的“75% 通道压缩”采用结构化通道裁剪：按卷积核权重的 L1 范数挑出要留下的输出通道，再把下一层对应的输入通道一起裁掉。

注意别误会“75%”的意思：它是中间层保留原来 75% 的通道（不是裁掉 75%，也没有把描述子维度砍成 75 维）：

text
中间通道：64 → 48，128 → 96，256 → 192
检测输出：仍然是 65 通道
描述输出：仍然是 256 维

因为大部分卷积层的输入和输出通道同时变少了，所以参数量下降的幅度远不止 25%，直接砍掉了 42.53%：

项目 原网络 压缩网络
参数量 1,300,865 747,633
参数减少比例 — 42.53%
FP32 参数理论存储量 5,203,460 字节（约 4.96 MiB） 2,990,532 字节（约 2.85 MiB）
描述子维数 256 256

（这里只按参数个数 × 4 字节算了理论存储，不包含文件封装和运行时显存；另外本次没做统一的推理耗时基准对照，不能直接写成“速度提升了 42.53%”。）

4. 总结

把原理和实验串起来复盘一遍，这次学习下来最关键的 5 点认识是：

  1. “流程跑通”和“达到官方水平”是两码事：本地从头训的模型完整走完了合成预训练、单应适应和联合训练，在简单变换下也表现不错，但一上 HPatches 真实场景，和官方权重依然差着一截（尤其在视角变化上）。
  2. 找得到点，不代表配得对：微调前 45° 旋转组的检测重复率其实高达 83.83%，但匹配正确率只有 12.56%——点明明都找到了，卡脖子的是描述子旋转后认不出来。
  3. 硬加困难增强往往是有代价的：大角度微调把 30° 旋转拉高了不少，但也让 10° 小角度和 HPatches 整体表现出现了回退。
  4. 通道压缩必须连着“恢复训练 + 真实任务指标”一起看：保留 75% 中间通道能减掉 42.53% 的参数量，但直接裁剪官方权重会直接失效；靠蒸馏做恢复训练后，才真正拿到了 83.61% 的匹配正确率和 79.31% 的单应成功率@3px。
  5. 指标口径决定结论靠不靠谱：参数量少了 42.53% 不等于提速 42.53%，RANSAC 返回了矩阵不等于算准了，没有真值时的内点多也不等于准确率高。

整体来看，这次实验最明确的一条实用结论是：官方权重按 75% 通道裁剪并配合蒸馏恢复后，能在少掉 42.53% 参数的前提下，在 HPatches 上基本保住原版表现（匹配正确率 83.61%，单应成功率@3px 79.31%）；而大角度旋转能力和书封面这类重复纹理场景下的误匹配，后面还需要继续改进。
