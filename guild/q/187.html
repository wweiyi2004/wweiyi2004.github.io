前面三个专题（特征提取、稀疏匹配、误匹配剔除）全都在走“先各自找关键点 → 再跨图配对”的路线。

但只要碰到室内白墙、光溜溜的桌面、运动模糊、大片重复地砖，这套流水线第一步就直接断气——如果检测器在两张图里压根没在同一个地方检出角点，后面再厉害的 LightGlue 也变不出匹配来。

2021 年，LoFTR 开创了 Detector-Free（无检测器）半稠密匹配的新范式：直接跳过检测器！把两张图的 1/8 粗网格当成天然候选点，放进 Transformer 里看清全局上下文后直接做粗匹配，再拿筛出来的粗网格对去 1/2 细图里把坐标精修到亚像素！

不过 LoFTR 虽然彻底打通了弱纹理场景，但它有两个老大难问题：

  1. 太慢：一张 480×640 图的 1/8 粗网格有 60×80 = 4800 个 token，跑多层跨图 Transformer 和局部细窗口 Transformer 延迟很高；
  2. 近似注意力不够聚焦 / 易受干扰：LoFTR 为了降复杂度用了 Linear Attention，分布太平不够锐利，且在极端视角和杂乱背景里容易被无关区域带偏。

后面四篇论文（QuadTree、TopicFM、Efficient LoFTR、EDM）全都是在 LoFTR 这套“粗到细”骨架上，针对**“注意力怎么又快又准”和“细精修怎么又轻又无偏”**做文章。先看全景对比表：

1.1 第一步 & 第二步：为什么必须用 Linear Transformer？

把 60×80 展平后，每张图有 N=4800N = 4800N=4800 个 token，特征维 C=256C = 256C=256。算一笔矩阵乘法的账：

  • 标准 Softmax Attention：先算 QK⊤Q K^\topQK⊤ 得到 [4800 × 4800] 的巨型注意力矩阵，再乘 VVV [4800 × 256]，计算量是 O(N2C)≈48002×256O(N^2 C) \approx 4800^2 \times 256O(N2C)≈48002×256，4 层跑下来显存和速度直接爆炸！
  • LoFTR 的 Linear Attention：把指数归一化核替换成显式特征映射 ϕ(x)=elu⁡(x)+1\phi(x) = \operatorname{elu}(x) + 1ϕ(x)=elu(x)+1（保证非负），于是原本不能拆分的矩阵连乘就能利用结合律改变乘法顺序——先算后面两项 ϕ(K)⊤V\phi(K)^\top Vϕ(K)⊤V：

LinearAttention⁡(Q,K,V)=ϕ(Q)(ϕ(K)⊤V)\operatorname{LinearAttention}(Q, K, V) = \phi(Q)\Big(\phi(K)^\top V\Big) LinearAttention(Q,K,V)=ϕ(Q)(ϕ(K)⊤V)

看一眼改变顺序后的矩阵维度变化：

  • 先算 ϕ(K)⊤V\phi(K)^\top Vϕ(K)⊤V：[256 × 4800] × [4800 × 256] = [256 × 256]（只有 256×256 小方阵！）；
  • 再拿 ϕ(Q)\phi(Q)ϕ(Q) 去乘：[4800 × 256] × [256 × 256] = [4800 × 256]！

计算量从 O(N2C)O(N^2 C)O(N2C) 暴降到 O(NC2)O(N C^2)O(NC2)（4800×25624800 \times 256^24800×2562），瞬间少了将近 20 倍！经过 4 轮 Self + Cross 交互，哪怕是白墙上的一个网格点，也吸收了旁边窗户、天花板线条的全局相对位置信息，变得独一无二。

1.2 第三步：粗匹配（Dual-Softmax）

1.3 第四步：细匹配精修（Coarse-to-Fine Refinement）

粗匹配坐标落在 1/8 网格中心，误差还有几个像素。LoFTR 对 McM_cMc​ 里的每一对粗匹配 (i,j)(i, j)(i,j) 做四步精修：

  1. 换算到 1/2 细特征图（240×320）的对应中心位置，分别在图 A 和图 B 上切出 5×55 \times 55×5 的局部小窗口（含 25 个细特征向量）；

2. QuadTree Attention：用“四叉树 Top-K 聚焦”替代糊成一团的线性注意力

论文：QuadTree Attention for Vision Transformers（ICLR 2022）

2.1 Linear Attention 到底丢掉了什么？

LoFTR 用 ϕ(Q)ϕ(K)⊤\phi(Q)\phi(K)^\topϕ(Q)ϕ(K)⊤ 换掉了 softmax⁡(QK⊤)\operatorname{softmax}(QK^\top)softmax(QK⊤)，虽然速度快了，但把指数函数的“赢家通吃”特性给丢掉了——结果注意力权重铺得太平均、太糊，一个点往往把无关背景也混进来一起加权，细粒度匹配精度受损。

QuadTree Attention 问：能不能依然保持 O(N)O(N)O(N) 线性复杂度，却跑真正的 Softmax Attention？

2.2 一步步看四叉树注意力怎么“一级级放大找人”

以 1/8 粗特征图（60×80）为例，QuadTree 先通过平均池化顺手建出一棵 3 层图像金字塔：1/32 (15×20 = 300 格) → 1/16 (30×40 = 1200 格) → 1/8 (60×80 = 4800 格)。

现在拿图 A 的某个 Query，去和图 B 算跨图注意力（设每层只挑 Top-KKK 个最相关区域，例如 K=8K = 8K=8）：

text
第 1 层（最粗 1/32，共 300 格）：
   算全图标准 Softmax Attention（才 300 个 Key，极快！）
   ──▶ 挑出注意力得分最高的 Top-K（8 个）粗网格！
            │
            ▼  每个粗网格裂变成 2×2 = 4 个子网格（四叉树一分四！）
第 2 层（中层 1/16，共 1200 格，但只看 4K = 32 格！）：
   只在刚才入选的 32 个子网格里算标准 Softmax Attention（剪掉 97% 无关背景！）
   ──▶ 再从中挑出得分最高的 Top-K（8 个）中层网格！
            │
            ▼  继续一分四
第 3 层（最细 1/8，共 4800 格，但只看 4K = 32 格！）：
   只在最精准的 32 个细网格里算标准 Softmax Attention！
            │
            ▼  把三层各自聚合出来的消息按多尺度权重加在一起，输出最终更新特征！

算一笔复杂度账：

  • 无论特征图有多大，最细层每个 Query 永远只需要和固定 4K4K4K 个（如 32 个）精选出来的 Key 算真 Softmax Attention，总复杂度严格是 O(N⋅4K)=O(N)O(N \cdot 4K) = O(N)O(N⋅4K)=O(N)！
  • 而且它顺带实现了天然的多尺度融合（粗层看全局大方向，细层死盯精准对应局部），直接替换掉 LoFTR 的 Linear Attention 后，匹配精度稳定提升。

（论文里区分了两种变体：QuadTree-A 只在最细层或统一重归一化适合图像分类/目标检测，QuadTree-B 在每一层独立做归一化后加权融合，更适合图像匹配这类密集几何对应任务。）

3. TopicFM：先给画面分“潜在语义主题”，再在同主题内部匹配

论文：TopicFM: Robust and Interpretable Topic-Assisted Feature Matching（AAAI 2023）

3.1 为什么说“按语义主题分组”能抗大视角与大尺度变化？

当两张照片视角差很大，或者一张拍全景、一张拍特写（尺度差 3～4 倍）时，纯空间网格级别的全局交互很容易被各种杂乱背景干扰。

TopicFM 借用了文本主题模型（LDA）的思想：一张图里的所有粗网格，其实可以软归类到 MMM 个潜在语义主题（Latent Topics，比如天空、屋顶、砖墙、窗户、地面——完全自发学出来，不需要任何人工语义分割标注！）。

3.2 一步步拆解 TopicFM 的三大核心步骤

假设维护 MMM 个可学习的主题原型向量 T∈RM×C\mathbf{T} \in \mathbb{R}^{M \times C}T∈RM×C（例如 M=100M = 100M=100）：

text
粗特征图 F̃^A [N_A, C]、F̃^B [N_B, C]
        │
        ▼  第一步：主题推断（Topic Inference）
           每个网格特征和 M 个主题向量算相似度 + Softmax
           ──▶ 得到每个网格的主题分布 θ^A [N_A, M]、θ^B [N_B, M]
        │
        ▼  第二步：主题本身跨图对齐 + 主题内精细注意力（Topic-Assisted Feature Augmentation）
           ① 用 θ 加权聚出图 A 和图 B 各自的 M 个主题摘要特征 T^A、T^B
           ② 只在 M 个主题之间做跨图注意力更新（M=100 极快！让两张图的“窗户主题”先对齐）
           ③ 按最大概率把每个网格归入对应主题 m ∈ {1..M}，
              只在“同属主题 m”的图 A 网格和图 B 网格之间做精准的 Self/Cross Attention！
        │
        ▼  第三步：粗匹配 + 主题感知的细精修
           既利用增强特征算 Dual-Softmax 粗匹配，又融合主题概率一致性，最后进细精修

注意它的训练监督巧思：怎么保证两张图里“同一面墙”一定会被分到同一个编号的主题里，而不是图 A 分成主题 3、图 B 分成主题 17？

TopicFM 直接利用真值粗匹配对 (i,j)∈Mcgt(i, j) \in M_c^{\mathrm{gt}}(i,j)∈Mcgt​ 构造了主题一致性损失 LtopicL_{\mathrm{topic}}Ltopic​——如果图 A 的网格 iii 和图 B 的网格 jjj 是真匹配，就用交叉熵/KL 散度逼着它们的主题概率分布 θiA\theta_i^AθiA​ 和 θjB\theta_j^BθjB​ 高度一致！结果不仅精度更高、计算更集中，把主题图画出来还能直接看到清晰的语义区域划分。

4. Efficient LoFTR (ELoFTR)：全面提速 2.5 倍，精度还反超老版！

论文：Efficient LoFTR: Semi-Dense Local Feature Matching with Sparse-Like Speed（CVPR 2024）

这是 LoFTR 原班人马交出的“官方全面换代版”。它动了三把极其精准的手术刀，每一刀都既提速又涨点。

4.1 手术刀一：主干换用 RepVGG（训练多分支，推理压成单路）

原版 LoFTR 用标准 ResNet-FPN，残差相加和多分支读写显存带宽开销不小。ELoFTR 把主干换成 RepVGG 结构——训练时保留 3×3 + 1×1 + Identity 多分支好优化，推理部署前通过结构重参数化（Reparameterization）直接融合成一条光溜溜的 3×3 卷积直道，主干耗时先砍掉一大块。

4.2 手术刀二：聚合注意力（Aggregated Attention）——浓缩 Token + 真 Softmax + RoPE！

原版 LoFTR 之所以不敢用真 Softmax，是因为 1/8 粗特征图上有 4800 个 token。但作者仔细观察特征图后发现：相邻的 4×4 网格里，高层语义特征高度相似冗余！

于是 ELoFTR 彻底扔掉了近似的 Linear Attention，发明了聚合注意力（Aggregated Attention）：

        └───────────────────────┬─────────────────────────┘

                                   （300×300 矩阵小到飞起，还能直接吃 FlashAttention 硬件加速！）
                                │
                                ▼  ③ 上采样还原回 [C, 60, 80] + 和局部 Depthwise Conv 细节残差融合！

一举两得：长度缩为 1/16 后，二次注意力矩阵的面积直接缩小了 162=25616^2 = 256162=256 倍；同时因为找回了真正的 Softmax 聚焦力和 RoPE 相对位置编码，表达能力反而暴打原版 Linear Attention！

4.3 手术刀三：两阶段相关性精修——彻底砍掉细 Transformer，消除“期望拉偏”！

回忆一下原版 LoFTR 的第四步精修，它有两个大毛病：

  1. 太慢：假设粗匹配出了 2000 对，每对切两个 5×5 窗口去跑局部 Transformer，就是 2000 个 batch 的 Transformer，极其耗时；
  2. 存在“空间方差误差（Spatial Variance Error）”：看下面这个直观例子——
text
假设在图 B 的 5×5 窗口里，真匹配在正中心 (0, 0)（概率 0.6），
但左上角 (-2, -2) 碰巧有个相似纹理杂点分走了 0.4 的概率：

  原版 LoFTR（直接全局求期望）： 0.6*(0,0) + 0.4*(-2,-2) = (-0.8, -0.8)  ← 被杂点硬生生拉偏了 0.8 像素！

ELoFTR 直接扔掉细粒度局部 Transformer，换成了极其轻快且无偏的两阶段相关性精修（Two-Stage Correlation Refinement）：

  • 第一阶段（像素级锁定，彻底清杂点）：在 1/2 或原图局部窗口里，拿图 A 窗口内所有特征和图 B 窗口内所有特征算局部相关性矩阵并做 Dual-Softmax，直接用 argmax 锁死得分最高的那对整数像素位置 (u∗,v∗)(u^*, v^*)(u∗,v∗)！刚才左上角那个 0.4 概率的杂点直接被一刀切掉！
  • 第二阶段（亚像素微调，只看 3×3 贴身邻域）：只在刚锁定的整数像素 (u∗,v∗)(u^*, v^*)(u∗,v∗) 周围极小的 3×33 \times 33×3 贴身九宫格里算一次 Softmax 期望，拿到精确的亚像素偏移 (Δu,Δv)(\Delta u, \Delta v)(Δu,Δv)！

结果就是：ELoFTR 在 MegaDepth、ScanNet 和视觉定位基准上精度全面超越 LoFTR，速度却快了约 2.5 倍，第一次让半稠密匹配跑出了逼近稀疏匹配（SuperPoint + LightGlue）的速度！

5. EDM（Efficient Deep Feature Matching）：全链路极简低延迟

论文：EDM: Efficient Deep Feature Matching（Xi Li, Tong Rao, Cihui Pan）
防混淆提示：CVPR 2025 还有另一篇同名论文 EDM: Equirectangular Projection-Oriented Dense Kernelized Feature Matching，专做 360∘360^\circ360∘ 全景图稠密匹配，我们在 专题（五） 单独拆解。

5.1 核心思路：从头到尾审视每一毫秒花在了哪里

哪怕到了 ELoFTR，如果要在实时 SLAM、无人机或者边缘端用 ONNX / TensorRT 跑，骨干、交互和精修三个阶段依然还有压缩空间。这篇 EDM 对无检测器管线做了全链路减负：

text
输入图像 A、B
   │
   ▼  第一步：更深但通道更窄的轻量骨干（改通道版 ResNet-18）
      减少通道宽度降低显存带宽和计算量，靠网络深度保住高层语义感受野
   │
   ▼  第二步：相关性注入模块 CIM（Correlation Injection Module）
      只在深层小尺寸特征图上做高效全局交互，然后把跨图相关性从全局到局部逐级“注入”回较浅特征层，
      避免在较大特征图上反复跑沉重的全局 Transformer！
   │
   ▼  第三步：双向筛选粗匹配
      用简洁有效的筛选策略剔除粗匹配阶段的歧义候选
   │
   ▼  第四步：轻量双向坐标轴回归头（Lightweight Bidirectional Axis-Based Regression Head）
      不再构造高分辨率的 2D 局部相关性热力图（复杂度 W×W），
      而是从隐特征里直接沿水平（X 轴）与垂直（Y 轴）解耦回归双向亚像素坐标（复杂度降到 2W 级别）！
   │
   ▼
输出精准亚像素匹配对（官方直接支持 ONNX / TensorRT 极速部署）

重点记一下它的两处工程巧思：

  1. CIM（相关性注入）：传统方法在 1/8 尺度上硬扛多层交互，而 CIM 把重头交互推到更深更小的尺度，再把交互好的跨图关联信息像金字塔一样逐级注入回高分辨率层，兼顾全局感受野和低延迟；
  2. 双向坐标轴回归头：精修阶段绕开了耗显存、耗访存的 2D 局部热力图构造，把二维位置回归分解为双向一维坐标轴回归，让整条管线非常规整，极容易被 TensorRT 编译成超高帧率的推理引擎。

6. 总结：无检测器半稠密匹配怎么学、怎么选？

  • 打牢根基：把 LoFTR 的 1/8 粗特征 + Linear Attention 结合律 + Dual-Softmax + 5×5 窗口期望精修 彻底吃透，你就掌握了整个无检测器赛道的通用语言；
  • 看注意力怎么升级：QuadTree 用金字塔四叉树 Top-K 找回真 Softmax，TopicFM 用潜在语义主题把交互锁进同语义区域（还附带强可解释性）；
  • 科研与工程综合首选：Efficient LoFTR (ELoFTR)——“聚合注意力 + 两阶段相关性精修”把速度和精度同时拉满，是目前最推荐的半稠密基线；
  • 极致低延迟 / TensorRT 部署：重点研究 EDM 的窄深主干 + CIM + 双向坐标轴回归头设计。

半稠密匹配已经能在弱纹理区配出几千对点了，但如果面对极端大视角、跨昼夜/跨季节、甚至 360∘360^\circ360∘ 全景图强畸变，要求全图每一个像素都给出精确 Warp 坐标和置信度呢？下一篇 专题（五）：稠密特征匹配，我们深入拆解 RoMa 和 CVPR 2025 全景 EDM。
