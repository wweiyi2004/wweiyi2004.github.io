前言与背景

如果你已经看过本系列的上一篇专题梳理——无检测器半稠密匹配专题总览，一定还记得一个贯穿整个视觉 Transformer 与半稠密匹配领域的“老冤家”：标准自注意力/交叉注意力的二次方复杂度 O(N2)O(N^2)O(N2)。

这篇精读的主角是发表于 ICLR 2022 的经典论文 QuadTree Attention for Vision Transformers（作者：Shitao Tang、Jiahui Zhang、Siyu Zhu、Ping Tan，来自西蒙菲莎大学 SFU 与阿里巴巴达摩院 AI Lab，官方代码开源在 https://github.com/Tangshitao/QuadtreeAttention）。

在 无检测器半稠密匹配专题总览 的技术演进路线里，LoFTR（CVPR 2021）首次把 Transformer 搬到无检测器（Detector-Free）半稠密特征匹配中，让网络不再依赖容易在弱纹理区域失效的关键点检测器，直接对整张 1/81/81/8 分辨率特征图做全局信息交互。但问题马上就来了：一张 640×480640 \times 480640×480 的照片，下采样 8 倍后还有 60×80=480060 \times 80 = 480060×80=4800 个网格点（token）。如果跑标准 Transformer，光是注意力矩阵就有 4800×4800≈2.3×1074800 \times 4800 \approx 2.3 \times 10^74800×4800≈2.3×107 个元素，显存和算力瞬间爆炸。

为了绕开 O(N2)O(N^2)O(N2) 这堵墙，前代工作尝试了四条路，却各自卡在了不同的瓶颈上：

  1. 线性近似注意力（Linear Attention，如 LoFTR 采用的 Katharopoulos et al., 2020）：通过核函数把 Softmax 拆开，先算 K⊤VK^\top VK⊤V 再乘 QQQ，把复杂度压成了 O(N)O(N)O(N)。但它本质上是对标准注意力的低秩平滑近似，丢掉了尖锐的局部聚焦能力。作者在论文附录的注意力可视化里一针见血地指出：Linear Attention 往往把注意力“糊”在一大片无关区域上，在视觉匹配这类讲究精准定位的任务中明显吃亏。
  2. 空间降采样注意力（Spatial Reduction Attention，如 PVT / PVTv2）：保持 Query 尺寸不变，直接把 Key 和 Value 池化缩小（比如缩到 8×88 \times 88×8）再算注意力。省算力是省了，但 Key/Value 一旦变粗，像素级细粒度细节直接丢失。
  3. 局部窗口注意力（Local Window Attention，如 Swin Transformer、Focal Transformer）：只在局部小窗口里算注意力，虽然显存省、细节也在，但单层里丢失了全局长距离依赖（比如 Focal Transformer 第一阶段只覆盖全图约 1/61/61/6 的区域）。更致命的是，对于跨图像特征匹配（Cross-Attention），图像 A 里的一块墙角可能对应图像 B 里的任意角落，根本没法提前画定局部窗口！
  4. K-NN 稀疏注意力（如 KVT、Explicit Sparse Transformer）：虽然最后只聚合得分最高的 Top-KKK 个 token，但为了挑出这 Top-KKK，它还是得先把所有 Query-Key 对两两算一遍得分，总复杂度依然是 O(N2)O(N^2)O(N2)。

那 QuadTree Attention 是怎么一句话破局的？

核心直觉：一张图片（或两张待匹配图像）里，和当前像素块真正相关的区域其实只占极小一部分，绝大部分背景都是无关的。与其在最细分辨率上傻傻地“全图两两算一遍”，不如给 Q,K,VQ, K, VQ,K,V 建一座从粗到细的 Token 金字塔：先在极低分辨率的粗层扫一遍全图，挑出得分最高的 Top-KKK 个候选区域；到了下一层更细的分辨率，只在这 Top-KKK 区域分裂出来的 2×22 \times 22×2 子块里算注意力，其余无关区域直接剪枝跳过！

因为二维图像块每往下一层就会一分为四（就像计算机图形学里的四叉树 QuadTree），这篇论文就把这套机制命名为 QuadTree Attention。它一举同时拿下了四件以前难以兼得的事：

  • 全局视野：最粗层覆盖 100% 画面，不存在窗口盲区；
  • 细粒度精度：真正相关的候选区一路细分到最高分辨率，不损失细节；
  • 线性复杂度 O(KHW)O(KHW)O(KHW)：剪掉海量无关区域，随图像分辨率线性增长；
  • 自注意力与交叉注意力通吃：既能替换 LoFTR、STTR 里的跨图匹配模块，也能替换 PVTv2、Swin 里的通用视觉骨干。

2.1 回顾标准注意力与二次方瓶颈

给定两组图像特征嵌入 X1\mathbf{X}_1X1​ 和 X2\mathbf{X}_2X2​（当 X1=X2\mathbf{X}_1 = \mathbf{X}_2X1​=X2​ 时就是自注意力 Self-Attention，当 X1≠X2\mathbf{X}_1 \neq \mathbf{X}_2X1​=X2​ 时就是跨图交叉注意力 Cross-Attention）。标准 Transformer 先用三组可学习的线性投影矩阵 Wq,Wk,Wv\mathbf{W}_q, \mathbf{W}_k, \mathbf{W}_vWq​,Wk​,Wv​ 生成查询（Query）、键（Key）和值（Value）：

Q=WqX1,K=WkX2,V=WvX2\mathbf{Q} = \mathbf{W}_q \mathbf{X}_1, \qquad \mathbf{K} = \mathbf{W}_k \mathbf{X}_2, \qquad \mathbf{V} = \mathbf{W}_v \mathbf{X}_2 Q=Wq​X1​,K=Wk​X2​,V=Wv​X2​

接着计算所有 Query 和 Key 之间的点积相似度，做 Softmax 归一化后对 Value 加权求和（原论文公式 1）：

Y=softmax⁡ ⁣(QK⊤C)V\mathbf{Y} = \operatorname{softmax}\!\left(\frac{\mathbf{Q}\mathbf{K}^\top}{\sqrt{C}}\right)\mathbf{V} Y=softmax(C​QK⊤​)V

我们来逐个确认符号含义：

  • Q,K,V∈RN×C\mathbf{Q}, \mathbf{K}, \mathbf{V} \in \mathbb{R}^{N \times C}Q,K,V∈RN×C：拉平后的特征序列，其中 N=H×WN = H \times WN=H×W 是图像块（token）总数，CCC 是通道维度；
  • C\sqrt{C}C​：缩放因子，防止维度较大时点积方差过大导致 Softmax 梯度饱和；
  • QK⊤∈RN×N\mathbf{Q}\mathbf{K}^\top \in \mathbb{R}^{N \times N}QK⊤∈RN×N：完整的两两相关性矩阵。

痛点在哪？ 就在这个 N×NN \times NN×N 的大矩阵。对于视觉密集任务，图像分辨率涨 2 倍，token 数量 N=H×WN = H \times WN=H×W 就涨 4 倍，注意力计算量和显存就会暴涨 42=164^2 = 1642=16 倍！比如目标检测常用 800×1333800 \times 1333800×1333 的大图，第一阶段 1/41/41/4 分辨率特征图高达 200×334=66,800200 \times 334 = 66,800200×334=66,800 个 token，标准注意力的 N×NN \times NN×N 矩阵元素超过 44 亿个，根本没法算。

2.2 Token 金字塔构建与差异化下采样策略

为了避免直接在最细的 H×WH \times WH×W 网格上做全连接，QuadTree Attention 的第一步是先把 Q,K,V\mathbf{Q}, \mathbf{K}, \mathbf{V}Q,K,V 各自建成一座 LLL 层的 Token 金字塔。

假设输入特征图在最细层的分辨率是 H×WH \times WH×W（记为第 LLL 层），我们每次按步长 2 把高和宽各缩小一半，连续下采样 L−1L-1L−1 次，就得到从粗到细的 LLL 个层级：

Level 1  (H0×W0)  ⟶  Level 2  (2H0×2W0)  ⟶  ⋯  ⟶  Level L  (H×W)\text{Level } 1 \; (H_0 \times W_0) \;\longrightarrow\; \text{Level } 2 \; (2H_0 \times 2W_0) \;\longrightarrow\; \cdots \;\longrightarrow\; \text{Level } L \; (H \times W) Level 1(H0​×W0​)⟶Level 2(2H0​×2W0​)⟶⋯⟶Level L(H×W)

这里有一个非常容易被忽略、但原论文专门写出来的工程细节：Q,K\mathbf{Q}, \mathbf{K}Q,K 和 V\mathbf{V}V 的下采样方式并不是一刀切的！

  • 对于 Q\mathbf{Q}Q 和 K\mathbf{K}K：统一使用 平均池化层（Average Pooling） 逐级下采样。直觉很好理解：Q\mathbf{Q}Q 和 K\mathbf{K}K 负责“算粗略相似度、做区域筛选”，平均池化相当于把一个 2×22 \times 22×2 区域内的语义平滑汇总，既不增加额外参数，又能忠实反映这块区域的整体特征均值。
  • 对于 V\mathbf{V}V：按任务类型区分处理（除非特别说明）：
    • 在 交叉注意力任务（特征匹配、立体匹配）以及 QuadTree-A 中，同样使用 平均池化层（Average Pooling）；
    • 在 自注意力任务（图像分类、目标检测等，使用 QuadTree-B 时）中，使用 步长为 2 的 卷积-归一化-激活层（Conv-Norm-Act, stride=2） 来下采样 V\mathbf{V}V。

注意：为什么要对自注意力任务的 V\mathbf{V}V 改用带参数的 stride=2 卷积块？因为在分类/检测的骨干网络里，不同尺度下的 Value 本身承担着提取语义表征的重任，用可学习的卷积代替固定平均池化，能保留更丰富的纹理和边缘信息；而在特征匹配等交叉注意力任务里，我们需要两张图在粗层与细层保持高度一致的特征空间对齐，简单的平均池化反而更稳健、不易过拟合。

2.3 由粗到细的四叉树 Top-KKK 稀疏路由

金字塔建好了，接下来就是整篇论文最精彩的部分——怎么一层层把无关区域剪掉？

我们直接对着上面 core-mechanism.svg 的机制一（三格连环画），拿论文 Figure 2(a) 里的真实小例子（L=3L=3L=3 层，K=2K=2K=2，分辨率从 2×2→4×4→8×82 \times 2 \to 4 \times 4 \to 8 \times 82×2→4×4→8×8）走一遍手算推演：

  1. Step 1：在 Level 1（最粗层，2×22 \times 22×2 网格）做全图扫描
    • 此时图 A 的粗块 q1q^1q1 需要和图 B 里的全部 4 个粗块（记整张图区域为 Γi1\Gamma_i^1Γi1​）计算注意力得分。
    • 算出来 4 个格子的注意力分数分别是左上 0.1、右上 0.3、左下 0.2、右下 0.4（总和为 1.01.01.0）。
    • 我们设定 K=2K = 2K=2，于是立刻挑出得分最高的前两个格子：右上（0.3）和右下（0.4），把它们对应的空间范围记为下一层的候选区域 Γi2\Gamma_i^2Γi2​；而得分偏低的左半边（0.1 和 0.2）在更细的层级里将被直接放弃！
  2. Step 2：下沉到 Level 2（中等层，4×44 \times 44×4 网格）做稀疏细分
    • 原来图 A 里的粗块 q1q^1q1，到了 Level 2 会一分为四，分裂成 2×2=42 \times 2 = 42×2=4 个更细的子 Query（图中蓝框里的 4 个小格子，例如绿块 q2q^2q2 和黄块）。

2.4 多尺度消息聚合方案一：QuadTree-A（不重叠拼图 + 递归连乘）

现在我们已经拿到了所有层级 l∈{1,2,…,L}l \in \{1, 2, \dots, L\}l∈{1,2,…,L} 上算出来的局部注意力信息。接下来的核心问题是：对于最细层的第 iii 个 Query token qi\mathbf{q}_iqi​，怎么把从粗到细这 LLL 层的信息汇总成它的最终输出消息 mi\mathbf{m}_imi​？

作者一共设计了两种方案：QuadTree-A 和 QuadTree-B。我们先看最直觉、像“拼图”一样的 QuadTree-A。

原理直觉：
既然我们把画面按相关程度分成了不同精度——最不相关的区域只看粗层、中等相关的区域看中层、最相关的区域看最细层——那不如把这 LLL 层的互不重叠的差集区域拼成一张完整画面，就像一幅“中心高清、四周马赛克”的无缝拼图（见 core-mechanism.svg 左下角）！

用数学语言写出来（原论文公式 2、3、4）：

设 Γil\Gamma_i^lΓil​ 表示第 lll 层的候选区域（由第 l−1l-1l−1 层选出的 Top-KKK 展开得到，且 Γi1\Gamma_i^1Γi1​ 覆盖全图）。定义第 lll 层的不重叠残差区域为：

Ωil=Γil−Γil+1\Omega_i^l = \Gamma_i^l - \Gamma_i^{l+1} Ωil​=Γil​−Γil+1​

（最细层 l=Ll=Ll=L 没有下一层，所以 ΩiL=ΓiL\Omega_i^L = \Gamma_i^LΩiL​=ΓiL​）。可以看到，Ωi1,Ωi2,…,ΩiL\Omega_i^1, \Omega_i^2, \dots, \Omega_i^LΩi1​,Ωi2​,…,ΩiL​ 两两互不相交，合起来恰好完整铺满整张图像！

于是 QuadTree-A 把每一层在其专属区域 Ωil\Omega_i^lΩil​ 内聚合出的部分消息 mil\mathbf{m}_i^lmil​ 直接相加：

mi=∑1≤l≤Lmil(2)\mathbf{m}_i = \sum_{1 \le l \le L} \mathbf{m}_i^l \tag{2} mi​=1≤l≤L∑​mil​(2)

每一层的部分消息 mil\mathbf{m}_i^lmil​ 按该层注意力得分 sijls_{ij}^lsijl​ 对 Value 向量 vjl\mathbf{v}_j^lvjl​ 加权求和：

mil=∑j∈Ωilsijlvjl(3)\mathbf{m}_i^l = \sum_{j \in \Omega_i^l} s_{ij}^l \mathbf{v}_j^l \tag{3} mil​=j∈Ωil​∑​sijl​vjl​(3)

为了保证所有层级拼起来的总注意力权重和依然为 1（类似概率质量沿着四叉树逐级分配），QuadTree-A 用递归连乘的方式计算每一层的注意力得分：

sijl=sijl−1tijl(4)s_{ij}^l = s_{ij}^{l-1} t_{ij}^l \tag{4} sijl​=sijl−1​tijl​(4)

逐符号解释一下：

  • sijl−1s_{ij}^{l-1}sijl−1​：对应的父级 Query token 与父级 Key token 在上一层的注意力得分（原文记基础初值为 sij1=1s_{ij}^1 = 1sij1​=1；实际从第 1 层往下递归时，父节点把自身的总权重按比例拆分给子节点）；
  • tijlt_{ij}^ltijl​：在当前第 lll 层中，同一个父级块内部 2×22 \times 22×2 子块之间用标准 Softmax（公式 1）算出来的暂定局部分数（tentative attention score）；
  • vjl\mathbf{v}_j^lvjl​：第 lll 层金字塔上第 jjj 个位置的 Value 特征（QuadTree-A 中全部通过平均池化得到）。

拿小例子一算，马上就能发现 QuadTree-A 的致命短板！
假设在 Level 1 某个候选粗块拿到了 0.3 的权重，到了 Level 2 它的 4 个子块瓜分这 0.3，最高的一个子块可能只分到 0.3×0.4=0.120.3 \times 0.4 = 0.120.3×0.4=0.12；到了 Level 3 再瓜分一次，每个最细小块的得分 sij3s_{ij}^3sij3​ 就缩水得更厉害了！

作者在论文中非常坦诚地指出了 QuadTree-A 的两大硬伤：

  1. 越细层权重越衰减：因为分数是跨层连乘 sijl=sijl−1tijls_{ij}^l = s_{ij}^{l-1} t_{ij}^lsijl​=sijl−1​tijl​，层级越深、分数越小，反倒削弱了本来最有价值的细粒度特征对最终输出 mi\mathbf{m}_imi​ 的贡献；
  2. 粗层误差向下传导：只要粗层由于下采样模糊导致某个区域的 sij1s_{ij}^1sij1​ 估计偏小，它在后面所有细层里的分数就会被这个偏小的系数一路压低，细层根本没机会翻身！

2.5 多尺度消息聚合方案二：QuadTree-B（重叠独立计算 + 可学习加权 · 主推）

为了彻底治好 QuadTree-A 的两个毛病，作者提出了真正的主力方案——QuadTree-B（见 core-mechanism.svg 右下角）。

破局直觉特别干脆：
既然“硬凑成不重叠拼图 + 跨层连乘分数”会压死细层特征，那我们干脆别做拼图了！粗层只需要干一件事——帮下一层圈出候选名单 Γil\Gamma_i^lΓil​，至于每一层内部怎么给候选打分、怎么汇总消息，各层完全独立算自己的标准 Attention，互不连乘！最后把这 LLL 层算出来的多尺度消息，用一组可学习的权重 wilw_i^lwil​ 加权融合就行了！

公式简洁得令人赏心悦目（原论文公式 5、6）：

mi=∑1≤l≤Lwilmil(5)\mathbf{m}_i = \sum_{1 \le l \le L} w_i^l \mathbf{m}_i^l \tag{5} mi​=1≤l≤L∑​wil​mil​(5)

其中第 lll 层的部分消息 mil\mathbf{m}_i^lmil​ 直接在整个候选区域 Γil\Gamma_i^lΓil​ 上跑一次标准注意力：

mil=Attention⁡ ⁣(qil, KΓill, VΓill)(6)\mathbf{m}_i^l = \operatorname{Attention}\!\left(\mathbf{q}_i^l,\, \mathbf{K}_{\Gamma_i^l}^l,\, \mathbf{V}_{\Gamma_i^l}^l\right) \tag{6} mil​=Attention(qil​,KΓil​l​,VΓil​l​)(6)

逐符号拆解：

  • Γil\Gamma_i^lΓil​：第 lll 层被保留的候选区域（ΓiL⊂⋯⊂Γi2⊂Γi1\Gamma_i^L \subset \cdots \subset \Gamma_i^2 \subset \Gamma_i^1ΓiL​⊂⋯⊂Γi2​⊂Γi1​，所以不同层覆盖的空间范围是允许重叠的）；
  • KΓill,VΓill\mathbf{K}_{\Gamma_i^l}^l, \mathbf{V}_{\Gamma_i^l}^lKΓil​l​,VΓil​l​：把区域 Γil\Gamma_i^lΓil​ 内部所有 Key 和 Value token 堆叠成的局部矩阵（当 l≥2l \ge 2l≥2 时，长度固定为 4K4K4K）；
  • Attention⁡(⋅)\operatorname{Attention}(\cdot)Attention(⋅)：就是公式 1 的标准缩放点积 Softmax 注意力，在每一层内部独立归一化，权重和恒等于 1；
  • wilw_i^lwil​：可学习的融合权重，让网络自己决定对于当前 token，应该听几分全局粗语义（mi1\mathbf{m}_i^1mi1​）、听几分中尺度结构（mi2\mathbf{m}_i^2mi2​）、听几分最细局部细节（miL\mathbf{m}_i^LmiL​）。

为什么 QuadTree-B 全面碾压 QuadTree-A？

  1. 细层彻底解放：最细层 miL\mathbf{m}_i^LmiL​ 的 Softmax 权重和恒为 1，不再受粗层分数连乘的缩水惩罚，高频细节和精准位置得以满血保留；
  2. 抗粗层误差更强：粗层只要把真正相关的区域放进了 Top-KKK 名单里，哪怕粗层给它的相对排名不是第一、分数略有偏差，细层依然能凭高清特征把它精准拉回第一名（论文附录 Figure 5 的热力图直观印证了这一点）；
  3. 额外开销几乎为零：因为只是把 Ωil\Omega_i^lΩil​ 换成了 Γil\Gamma_i^lΓil​，每层参与计算的 token 数仍然是 4K4K4K，复杂度依然是严格的线性 O(KHW)O(KHW)O(KHW)！

2.6 多尺度位置编码 MPE（Multiscale Position Encoding）

我们知道，标准注意力对 token 的空间排列顺序是不敏感的（置换不变性，Permutation Invariant）——把一张图的像素块打乱再算点积，输出特征几乎没变化，这在特征匹配和目标检测这类吃空间坐标的任务里是绝对不能接受的。

而且 QuadTree Attention 有 LLL 个不同分辨率的金字塔层级，只给最细层加一次位置编码还不够。因此作者借鉴了 CSWin Transformer 里的局部增强位置编码（LePE，Dong et al., 2021），为金字塔设计了多尺度位置编码（MPE）：

  • 具体做法：在每一个金字塔层级 l∈{1,…,L}l \in \{1, \dots, L\}l∈{1,…,L} 上，分别用一个**权重不共享的深度可分离卷积（Unshared Depth-wise Convolution，DWConv）**直接作用在当前层的 Value 特征 Vl\mathbf{V}^lVl 上，把局部空间相对位置信息直接注入到多尺度特征中。
  • 为什么香？ 深度卷积参数量和计算量极小（在表 10 消融里，加了 MPE 后 QuadTree-B-b2 的 FLOPs 依然维持在 4.3G 几乎无变化），而且它天然适应任意输入分辨率（不用像绝对位置编码那样做双线性插值），在 COCO 目标检测上直接白嫖了 +1.3 AP 的大涨点！

3. 训练流程、真值构造与损失函数

读到这里，我们要先明确一个关于本论文定位的重要事实：

注意：QuadTree Attention 本身是一个即插即用的多尺度注意力核心模块，它并没有发明新的自定义损失函数，而是直接嵌入到四个主流视觉任务的既有框架中端到端训练——特征匹配接入 LoFTR、立体匹配接入 STTR、图像分类接入 PVTv2 / Swin、目标检测与实例分割接入 RetinaNet / Mask R-CNN。

3.1 特征匹配（LoFTR 框架）的数据构造与监督机制

  1. 训练数据怎么来？
    • 室内场景（ScanNet）：共 1,513 个三维扫描场景，提供对齐好的 RGB 图像、深度图（Depth Map）以及相机真实位姿（Ground-Truth Camera Pose）。作者按照重叠度得分（overlap score）在 [0.4,0.8][0.4, 0.8][0.4,0.8] 之间筛选，共采样了 2.3 亿（230M）对训练图像对。所有 RGB 图和深度图在训练与测试时均统一缩放至 640×480640 \times 480640×480。
    • 加速消融子集（LoFTR-lite）：完整 ScanNet 跑一次消融太耗算力，作者设计了 LoFTR-lite 配置——特征通道数砍半，只用 453 个训练场景，用来快速验证 QuadTree-A/B 和不同 KKK 值。
    • 室外场景（MegaDepth）：同样验证了室外建筑大视角匹配的泛化能力（Table 6）。
  2. 真值对应怎么标？
    • 因为 ScanNet 和 MegaDepth 同时具备每帧的深度图和相机内外参，在构造训练监督时（沿用 LoFTR 标准流程）：把图像 A 的粗网格点通过深度反投影到三维世界坐标，再经由两帧之间的相对相机位姿投影回图像 B 的像素平面，利用互投影一致性（mutual nearest projection）即可自动标出粗级真值匹配矩阵 Mcgt\mathcal{M}_c^{\text{gt}}Mcgt​ 以及细级亚像素真值坐标。
  3. 损失函数怎么算？
    • QuadTree Attention 论文直接沿用 LoFTR 框架的端到端训练目标（即粗级置信度矩阵的 Focal Loss / 负对数似然损失 + 细级局部坐标回归的加权 L2L_2L2​ 损失），未对匹配损失公式和权重系数做额外修改（原论文未重新抄写 LoFTR 的损失权重公式，我们下文配置表中如实标注“原文未披露，沿用 LoFTR 默认配置”）。
    • 一个值得关注的训练细节（表 1）：原版 LoFTR 官方报告的 57.6 AUC@20° 是用 64 张 GPU、batch size = 64 训出来的；而本文作者在算力有限的条件下，只用了 batch size = 8 训练 30 个 epoch。为了绝对公平，作者在同样的 batch size = 8 条件下重训了 Linear Attention（得到 56.6），结果 QuadTree-B 不仅在同一配置下反超重训版，换上 K=16 和 ViT 风格 Block 后（QuadTree-B*）更是在 batch size = 8 下直接飙到 61.6，领先 64 卡原版 LoFTR 整整 4.0 个点！

3.2 其他三类视觉任务的训练机制简述

  • 立体匹配（STTR 框架）：在合成数据集 Scene Flow FlyingThings3D（25,466 张图，960×540960 \times 540960×540）上训练。CNN 骨干输出 1/21/21/2 特征图后，过 6 层 128 通道的极线 QuadTree Transformer，再经由 10 次迭代的 Sinkhorn 最优传输层（Optimal Transport）和上下文精修层回归视差与遮挡图。训练 15 epoch，AdamW 优化器，OneCycle 学习率调度（初始/峰值学习率 6e-4），batch size = 8，沿用 STTR 损失函数。

4.3 时间与显存复杂度分析（附工程实测真相）

接下来我们严格推导一下 QuadTree Attention 为什么是线性复杂度。

在原论文附录 A.1 中，设最细层 Q,K,V\mathbf{Q}, \mathbf{K}, \mathbf{V}Q,K,V 的空间尺寸为 H×WH \times WH×W（共 N=HWN = HWN=HW 个 token），最粗层的空间尺寸为 H0×W0H_0 \times W_0H0​×W0​，共构建 LLL 层金字塔。若按从细到粗的层级跨度统计，第 lll 层的 token 数量为 HW4l−1\frac{HW}{4^{l-1}}4l−1HW​。

在最粗层（H0×W0H_0 \times W_0H0​×W0​）我们需要做一次全图注意力，点积对数量为 H02W02H_0^2 W_0^2H02​W02​；而在其余每一个较细层，每个 Query token 都只需要和父级 Top-KKK 展开出来的 4K4K4K 个 Key token 算一次点积（以及乘一次 Value，因此计算 QK⊤\mathbf{Q}\mathbf{K}^\topQK⊤ 与 AV\mathbf{A}\mathbf{V}AV 共带来系数 222，若把通道维 CCC 显式写出则每对乘加还需乘以 CCC）。

原论文附录 A.1 给出的 FLOPs 推导式如下（按省略常数通道因子 CCC 的标准记法）：

为什么理论 FLOPs 少了一大截，实际运行反而变慢了？
作者解释得非常坦白：他们当时只写了一个**朴素的自定义 CUDA Kernel（naive CUDA kernel）**来做四叉树稀疏索引与聚集（gather/scatter），几乎没做底层访存合并、Shared Memory 分块等深度硬件优化；而对照组 PVTv2 用的是 NVIDIA 经过十年打磨的 cuBLAS 稠密矩阵乘法（GEMM），硬件利用率极高。

注意：这是工程落地选型时必须盯紧的一点——FLOPs 低 ≠ 墙上时钟时间（wall-clock time）快。不过，QuadTree 在显存占用上的优势是立竿见影的（在 STTR 立体匹配上显存直降 37%，在 COCO 检测上显存直降 41%），这使得它能跑动原本会 OOM 的更高分辨率特征图。

  • 目标检测（COCO RetinaNet b0）：QuadTree-B 38.4 vs. QuadTree-A 37.0（+1.4 AP）。

附录 Figure 5 的跨图注意力可视化给出了铁证：SR Attention 和 Linear Attention 的热力图糊成一大片无关墙面；QuadTree-A 虽然能聚焦，但在粗层误差传递和递归连乘衰减的影响下，第 3 层的高亮区域依然偏散；而 QuadTree-B 从第 1 层到第 3 层稳步收缩，最终像激光笔一样死死钉在查询点对应的精准位置上。

此外，附录 C（Figure 3）还发现了一个有趣的现象：在 LoFTR-lite 训练曲线上，SR Attention 的训练 Loss 甚至比 QuadTree-A 还低，但验证集 AUC@20° 却明显更差——说明粗暴池化 Key/Value 容易让模型在训练集上死记硬背、泛化能力变弱；而 QuadTree-B 的训练 Loss 最低、验证集 AUC 最高，收敛与泛化兼得。

6. 优缺点、适用场景与局限边界

看论文不能只看高光，结合论文附录与实际工程落地的视角，我们来客观盘一盘 QuadTree Attention 的强项与边界。

6.1 核心优势

  1. 打破“全局视野”与“细粒度精度”的二选一僵局：通过由粗到细的四叉树金字塔，单个模块内就能同时看清整张图的宏观布局和目标区域的像素细节。
  2. 统一兼容自注意力与交叉注意力：Swin 这类局部窗口注意力很难直接搬到两张图的大视角匹配上，而 QuadTree 对 X1=X2 和 X1≠X2 天然一视同仁，因此能无缝成为 LoFTR、STTR 等跨图匹配任务的“最强外挂”。
  3. 显存随分辨率线性增长，高分辨率优势巨大：在 800×1333800 \times 1333800×1333 检测图上显存比 PVTv2 直降 41%，在立体匹配上能支撑 1/21/21/2 高清特征图而显存反降 37%。
  4. 对超参 KKK 不敏感，极易调参：KKK 取 8 或 16 就已接近性能上限，不需要把 KKK 调很大去硬撑精度。

6.2 短板与局限边界

  1. 实际推理吞吐受制于稀疏 CUDA 算子优化（工程最大痛点）：正如附录 D 坦白的那样，四叉树涉及不规则的 Top-KKK 排序与稀疏内存 Gather/Scatter，朴素 CUDA Kernel 的 GPU 并行效率远不如成熟优化的稠密 GEMM，导致出现“FLOPs 降了 42%、显存省了 41%，但单图前向耗时反而从 26ms 涨到 46ms”的倒挂现象。如果在强实时边缘端部署（且没有精力手写深度优化的 TensorRT / CUDA 融合算子），它的实际帧率未必优于 Linear Attention 或局部窗口注意力。
  2. 粗层剪枝不可逆带来的“漏选风险”：如果待匹配物体极小（在最粗层 15×2015 \times 2015×20 或 7×77 \times 77×7 上还不到半个格子，特征被平均池化完全淹没），或者场景里存在大面积高度相似的重复纹理（比如整齐的玻璃幕墙、砖墙、对称走廊），一旦最粗层没把真值区域选进 Top-KKK，后面所有细层就再也看不到它了。
  3. 特征图尺寸约束：因为需要连续做 L−1L-1L−1 次 2 倍下采样构建四叉树金字塔，输入特征图的长宽最好能被 2L−12^{L-1}2L−1 整除（否则就需要额外的 padding 和裁切逻辑）。
  4. 训练初期的稀疏路径梯度覆盖面有限：由于只沿 Top-KKK 路径计算细层注意力，每个样本在单次迭代中只有稀疏子集收到细层梯度，这也是为何 QuadTree-B 保留了覆盖全图的粗层消息 mi1\mathbf{m}_i^1mi1​ 协同反向传播才如此关键的原因。

6.3 适用场景与选型建议

  • 强烈推荐：对匹配精度与显存占用敏感的高分辨率视觉任务，例如基于 LoFTR 架构的室内外三维重建/SfM 离线特征匹配、高分辨率立体视差估计（STTR 类）、高分辨率航拍/医学图像的稠密预测骨干。
  • 谨慎评估：对毫秒级低延迟要求极高、且依赖标准 ONNX / TensorRT 通用算子快速部署的移动端/车载端实时管线（除非针对性优化稀疏 Gather/Attention 融合算子，否则可优先考虑后续基于轻量化/FlashAttention 友好的高效匹配架构）。

7. 总结

用 4 句话收束这篇 ICLR 2022 经典工作带给我们的核心启发：

  1. 设计哲学：视觉注意力天然具有高度空间稀疏性，与其像 Linear Attention 那样把全局注意力“糊化”成低秩近似，不如用四叉树金字塔由粗到细动态剪枝，把算力精准花在刀刃（Top-KKK 候选区）上，将复杂度严格压成线性 O(KHW)O(KHW)O(KHW)。
  2. 成败关键在 QuadTree-B：同样是四叉树，不重叠拼接 + 递归连乘分数的 QuadTree-A 会压低细层权重、放大粗层误差；而允许区域重叠、每层独立做 Softmax 再可学习加权融合的 QuadTree-B 彻底解放了细粒度特征，在所有任务上稳定领先。
  3. 半稠密匹配的直接价值：直接替换 LoFTR 粗级 Transformer 的线性注意力后，仅用 batch size 8 就在 ScanNet 上斩获 61.6 AUC@20°（反超 64 卡原版 LoFTR 4.0 个点），证明了“精准聚焦的跨图注意力”是半稠密特征匹配的核心提分引擎。
  4. 保持工程清醒：理论 FLOPs 和显存的线性化非常惊艳，但稀疏动态索引对底层 CUDA 算子高度敏感，在论文复现与实际落地时务必区分“算力/显存省”与“实际推理快”这两个维度。
