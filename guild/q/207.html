前言与背景

在做三维重建（SfM）、视觉定位与机器人导航的时候，传统针孔相机总有一个让人头疼的先天局限——视野太窄。拍一个室内大厅往往要走好多步、拍几十张照片，稍微转过一个拐角，两张图之间就没了重叠区域，匹配立刻断掉。

360° 全景图像（Omnidirectional Image） 天然解决了这个问题：一次快门就能把上下左右整整一个球面的环境全装进一张图里，几乎没有视觉盲区，也大大降低了数据采集成本。消费级全景相机（比如 RICOH THETA、Insta360）早已普及，全景图像也被广泛用在 VR 看房、机器人导航、全景 SLAM 和 360° 神经渲染等任务里。

不过，把 360° 全景图放进计算机视觉流水线做两视图特征匹配与相对位姿估计时，前代方法却卡在了两道非常尴尬的坎上：

  1. 投影方式怎么选都别扭：为了把球面图像存成二维矩阵喂给卷积网络，工程上最常用的有两种展开方式：
    • 等距柱状投影（ERP，Equirectangular Projection）：就像世界地图那样，把整个球面按经度 θ∈[−π,π]\theta \in [-\pi, \pi]θ∈[−π,π] 和纬度 ϕ∈[−π2,π2]\phi \in [-\frac{\pi}{2}, \frac{\pi}{2}]ϕ∈[−2π​,2π​] 直接摊平在一张宽高比 2:12:12:1 的矩形图里。它的好处是一张图保留了完整的 360° 全局视野，但代价是极点畸变极其严重（靠近天花板北极和地板南极的区域被横向扯得变形），而且最左边缘（θ=−π\theta=-\piθ=−π）和最右边缘（θ=+π\theta=+\piθ=+π）明明在球面上是同一条物理缝，在 2D 图像里却隔着整张图那么远。
    • 立方体贴图投影（Cubemap Projection）：把球面拆成上下左右前后 6 张没有畸变的普通透视图。虽然单张图看起来正常了，但要做两张全景图之间的匹配，就得把 6 张对 6 张拆开来独立跑很多轮推理（论文图 1 直观展示了这个痛点），不仅算力开销猛增，还把单张全景图原本最宝贵的全局大视野上下文给切碎了。
  2. 现有匹配范式在全景室内双双吃瘪：
    • 专门面向全景图的稀疏关键点方法（例如传统手工特征 SPHORB，或基于学习的关键点匹配器 SphereGlue、PanoPoint）高度依赖“先找关键点”。一进室内场景，满眼都是大片白墙、光滑天花板和重复的门框瓷砖，关键点根本找不全或配不对，稍微拉大视角、重叠率一降，误匹配就满天飞。
    • 而在透视图上大杀四方的无检测器稠密匹配方法（例如 LoFTR、DKM、RoMa），底层写死了2D 平面坐标与针孔相机几何假设。直接把 ERP 全景图硬塞进去，它们根本不知道极点是被拉宽的，也不知道画面左右两边其实是连在一起的，结果在畸变区和边界处大面积失灵。

这篇文章要精读的 EDM（Equirectangular Projection-Oriented Dense Kernelized Feature Matching），发表于 CVPR 2025（作者为 Dongki Jung、Jaehoon Choi、Yonghan Lee、Somi Jeong、Taejae Lee、Dinesh Manocha、Suyong Yeon，来自 NAVER LABS 与 马里兰大学 University of Maryland）。在我们的 稠密特征匹配专题总览 中，EDM 占据了一个非常独特且关键的生态位——它是首个专门面向 360° 全景 ERP 图像设计的学习型稠密特征匹配算法，成功把 DKM 这条“核化全局匹配 + 多尺度流场精修”的透视稠密匹配路线，完整地搬到了单位球面流形上。

如果用一句话概括 EDM 的破局思路，那就是：

不再把稠密匹配当成 2D 平面上的像素偏移映射 f→uf \to \mathbf{u}f→u，而是彻底改写成 3D 单位球面上的射线方向映射 f→Sf \to \mathbf{S}f→S（球面测地流）；粗匹配时用 3D 笛卡尔坐标做球面位置嵌入，精修时通过“3D 球面 →π\xrightarrow{\pi}π​ 2D ERP 做残差卷积 →π−1\xrightarrow{\pi^{-1}}π−1​ 3D 球面”的双向坐标变换，既享受到 2D 卷积与双线性采样的便利，又始终把几何约束牢牢锁死在单位球面上。

听起来很优雅对吧？别急着被“测地流”“高斯过程”“双向投影”这些名词吓到——接下来，我们就顺着原论文的脉络，配合两张专门绘制的矢量图解，一步一步把 EDM 的架构、公式、训练、推理和实验彻底拆开揉碎。

2. 核心模块逐层深挖

走通了全局流水线，现在我们把镜头拉近，将原论文第 3 节和第 4 节最硬核的三大球面设计（单位球面 3D 坐标、测地流精修、随机方位角旋转增强）拆成一步一图的极简图解，按**“痛点 → 原理直觉 → 精确公式与符号解释 → 具体数值/维度推演”**的节奏彻底讲明白。

2.1 球面坐标系与双向投影 π\piπ、π−1\pi^{-1}π−1

痛点：我们肉眼看到的 ERP 全景图是一张平平整整的 2D 矩形图片，但它的物理本质根本不是一张平面照片——它是一个球面相机把四面八方射向光心的单位方向射线，按经纬度强行摊平后的结果。如果不先建立 2D 图像坐标和 3D 单位球射线之间的精确换算桥梁，后面的一切球面建模都无从谈起。

原理直觉：想象你站在一个半径为 111 的透明玻璃球中心（这就是单位球面），往四周看：

  • 水平转头看一圈，对应经度 θ∈[−π,π]\theta \in [-\pi, \pi]θ∈[−π,π]（正好对应 ERP 图像的横轴 WWW）；
  • 抬头看天花板、低头看地板，对应纬度 ϕ∈[−π2,π2]\phi \in [-\frac{\pi}{2}, \frac{\pi}{2}]ϕ∈[−2π​,2π​]（正好对应 ERP 图像的纵轴 HHH）。

这样一来，ERP 图像上的任意一个 2D 球面坐标 u=(θ,ϕ)\mathbf{u} = (\theta, \phi)u=(θ,ϕ)，都唯一对应着单位球面上的一个 3D 笛卡尔点（也就是一条长度为 1 的相机射线）S=(Sx,Sy,Sz)\mathbf{S} = (S^x, S^y, S^z)S=(Sx,Sy,Sz)。

2.2 底座回顾：DKM 核化稠密匹配与高斯过程回归

EDM 是建立在 DKM（Dense Kernelized Feature Matching，CVPR 2023） 的框架之上的。要看懂 EDM 的 SSAM 改了哪里，我们需要先花两分钟把 DKM 的粗匹配引擎看明白。

核心直觉：在传统匹配里，找对应点往往是算一张巨大的相似度矩阵，然后做 Softmax 加权平均（类似交叉注意力）。DKM 换了一个更稳的视角——把它看作一个高斯过程（Gaussian Process，GP）回归问题：

  • 把图 B\mathcal{B}B 里的所有粗网格点当成“已知观测样本”：每个样本的“特征”是 fBf_{\mathcal{B}}fB​，它的“标签”是它在图 B\mathcal{B}B 里的空间位置（经过余弦位置编码后的向量 χB\chi_{\mathcal{B}}χB​）；
  • 现在来了一批“待查询点”——图 A\mathcal{A}A 的粗网格特征 fAf_{\mathcal{A}}fA​，让高斯过程根据特征之间的相似度核 KKK，回归出图 A\mathcal{A}A 每个位置最应该对应的图 B\mathcal{B}B 位置编码的后验均值 μA∣B\mu_{\mathcal{A}|\mathcal{B}}μA∣B​！

为什么不直接回归 2D 坐标，非要先套一层余弦嵌入 χB\chi_{\mathcal{B}}χB​？
因为真实图像里经常出现重复纹理（比如两扇一模一样的窗户）。如果直接拿普通回归去平均两个候选位置的 2D 坐标，算出来的平均值会落到两扇窗户正中间的墙面上（谁也没对上！）。把坐标先通过 cos(W·grid + b) 映射到高维频率嵌入空间（类似于通道编码 / 傅里叶特征），就能让 GP 的后验均值同时编码多峰分布信息（multimodality），再交给后面的 CNN 解码器结合上下文把正确的那个峰挑出来。

2.4 测地流精修（Geodesic Flow Refinement）

拿到了粗尺度的 3D 单位球面匹配 S^A→Bcoarse\hat{\mathbf{S}}_{\mathcal{A}\to\mathcal{B}}^{\text{coarse}}S^A→Bcoarse​ 后，接下来要进入最精彩、也最见工程巧思的一步：多尺度精修（原论文 Section 4.2 与 Figure 5）。

痛点：为什么不能直接套用 DKM 的线性残差精修？因为现在我们的匹配值 S^\hat{\mathbf{S}}S^ 是生活在单位球面上的 3D 向量！球面上两点之间的最短路径不是直线，而是沿球面弯曲的测地线（geodesic），所以两张全景图之间的稠密光流/对应场叫做测地流（geodesic flow）。如果你强行在 3D 空间里写 S^l=S^l+1+△S^l+1\hat{\mathbf{S}}^l = \hat{\mathbf{S}}^{l+1} + \triangle\hat{\mathbf{S}}^{l+1}S^l=S^l+1+△S^l+1：

  1. 会直接飞离单位球面：沿着球面切线加一个 3D 线性增量，新点的模长不再是 1，几何约束立刻被破坏；
  2. 没法在 2D 特征图上采样：ResNet50 提取出来的细尺度特征图 fBlf_{\mathcal{B}}^lfBl​ 终究是存放在 2D ERP 像素矩阵里的，PyTorch 的双线性插值（grid_sample）只认 2D 坐标 (θ,ϕ)(\theta, \phi)(θ,ϕ)，不认 3D 坐标 (Sx,Sy,Sz)(S^x, S^y, S^z)(Sx,Sy,Sz)！

原理直觉：既然“在球面上不好做线性加法和 2D 采样，而在 2D ERP 平面里一马平川”，EDM 干脆搭了一座双向传送门：

  • 每次精修开始前，先用正投影 π\piπ 把当前 3D 球面匹配“压回” 2D ERP 平面（3D →\to→ 2D）；
  • 在 2D ERP 平面里痛快地做双线性特征采样、算局部相关体、跑卷积 Refiner、把预测的 2D 残差直接线性加上去；
  • 每次精修加完残差后，立刻用反投影 π−1\pi^{-1}π−1 把更新好的 2D 坐标“抬回” 3D 单位球面（2D →\to→ 3D），再传给下一级更细的尺度！

2.5 随机方位角旋转增强（Randomized Azimuth Rotation Augmentation）

痛点：跟动辄百万级图像对的透视匹配数据集（比如 MegaDepth、ScanNet）相比，同时带高精度稠密深度图 + 对齐相机位姿的 360° 全景数据集极其稀缺（Matterport3D 训练集全部加起来也就 61 个场景、44,700 对图像）。如果不做强有效的数据增强，网络很容易过拟合到固定的室内视角朝向和固定接缝位置。

原理直觉：全景图有一个普通照片绝对没有的超能力——同一张 360° 球面图，只要绕着竖直轴换一个“正面零度经线”展开，就能无损变出无穷多张视觉上截然不同的 ERP 图像，而且画面的内容一点都没丢（没有透视图旋转后讨厌的黑边裁切）！

为什么 EDM 只做水平方位角（azimuth）旋转，而不做任意 3D 翻滚旋转呢？作者在 Section 2 里说得很坦诚：

  • 现实中绝大部分室内全景扫描（比如三脚架采集的 Matterport3D、Stanford2D3D、扫地机器人/自动驾驶车顶全景相机）都会尽量保持相机竖直向下方向与重力平行（gravity-aligned）；
  • 另一方面，全 SO(3) 旋转等变球面卷积（Spherical CNNs）算力开销过大，而通过训练期随机方位角旋转，就能在极低成本下让网络学会对任意水平朝向和任意接缝位置保持鲁棒。

精确公式（原论文 Section 4.3 与 Figure 6）：

IA←IA ⁣⟨π ⁣(TAaug π−1 ⁣(IAgrid))⟩DA←DA ⁣⟨π ⁣(TAaug π−1 ⁣(DAgrid))⟩TA←TA TAaug\begin{aligned} I_{\mathcal{A}} &\leftarrow I_{\mathcal{A}}\!\left\langle \pi\!\left(T_{\mathcal{A}}^{\text{aug}}\,\pi^{-1}\!\left(I_{\mathcal{A}}^{\text{grid}}\right)\right) \right\rangle \\ D_{\mathcal{A}} &\leftarrow D_{\mathcal{A}}\!\left\langle \pi\!\left(T_{\mathcal{A}}^{\text{aug}}\,\pi^{-1}\!\left(D_{\mathcal{A}}^{\text{grid}}\right)\right) \right\rangle \\ T_{\mathcal{A}} &\leftarrow T_{\mathcal{A}}\,T_{\mathcal{A}}^{\text{aug}} \end{aligned} IA​DA​TA​​←IA​⟨π(TAaug​π−1(IAgrid​))⟩←DA​⟨π(TAaug​π−1(DAgrid​))⟩←TA​TAaug​​

注意：关键在于“三者联动”——图像 III、深度 DDD 跟着新网格重新采样，同时相机外参位姿 TTT 右乘 TaugT^{\text{aug}}Taug。这样一来，像素对应到世界坐标系下的三维点位置纹丝不动，两帧之间的相对几何真值依然 100% 精确，但网络在每次迭代中看到的物体水平位置、接缝切开的位置、两帧之间的相对水平偏航角全都千变万化！后面 Table 3 消融实验会证明，这看似简单的几行代码，居然在最终模型上直接带来了 +10.51 的 AUC@5° 暴涨。

3. 训练流程、真值构造与损失函数

理解了网络的前向结构，我们再来看 EDM 是怎么训出来的：数据从哪来、真值怎么标、损失怎么算、超参数怎么设。

3.1 数据准备与 Matterport3D 天空盒位姿还原

训练 EDM 需要三样东西：ERP 彩色图像、逐像素真值深度图、对齐的相机位姿。

EDM 的全部训练都在 Matterport3D 数据集上完成（共 90 个室内场景、10,800 个带纹理网格的全景扫描点）。不过 Matterport3D 有一个让很多做全景研究的人头疼的历史坑：它用来拼 ERP 图的 6 面天空盒（skybox）图像官方并没有直接提供位姿和深度标注！以前的工作要么拿三角网格重新渲染，要么跑一遍 360° SfM 去反推位姿，既麻烦又容易引入误差。

EDM 作者在 Section 5.1 分享了一个非常实用的实验发现：

  • Matterport3D 每个全景站点原本提供 18 个普通相机视角（6 个水平旋转 ×\times× 3 个俯仰角）的精确位姿；
  • 经过实测，直接把这 18 个视角里的第 12 个相机位姿当作第 2 张天空盒图像的位姿完全没有偏差，剩下 5 张天空盒图像的位姿只需从第 2 张出发分别绕各方向旋转 90∘90^\circ90∘ 即可直接算出！

拿到对齐的 ERP 图像、深度图和位姿后，怎么挑出适合做双视图匹配的“重叠图像对”？

  1. 严格遵循 Matterport3D 官方场景划分：61 个场景做训练，11 个做验证，18 个做测试（场景严格隔离，杜绝数据泄漏）；
  2. 在球面坐标系下，把帧 A\mathcal{A}A 的 ERP 深度图投影变换到帧 B\mathcal{B}B；
  3. 像素深度差小于阈值（论文举例为 0.1）的像素算作内点（inlier），计算内点占整图总像素数的比例作为重叠率（overlap ratio）；
  4. 保留重叠率 >30%> 30\%>30% 的图像对：最终构造出 44,700 对训练样本 和 4,575 对测试样本，并统一将 ERP 图像与深度图缩放到 640×320640 \times 320640×320。

4.1 一步步走通真实推理链路

假设现在你手里有两张用 Insta360 拍的室内全景照片，想算出两张照片之间的相机相对旋转 RRR 和平移方向 ttt，完整推理一共有 6 步：

  • 第一步：图像预处理
    把两张 ERP 图像统一缩放到 640×320640 \times 320640×320（[1, 3, 320, 640]）并做常规标准化。不需要深度图、不需要内参（ERP 图像的经纬度网格天生就是标准化的球面相机模型）。
  • 第二步：多尺度特征提取
    两张图同时送入共享权重的 ResNet50 编码器，一次前向拿到步长 {32, 16, 8, 4, 2, 1} 的全套多尺度特征图。
  • 第三步：SSAM 粗尺度全局对齐
    在粗尺度上构造 3D 单位球网格并做球面余弦位置嵌入 χB\chi_{\mathcal{B}}χB​，跑一次高斯过程回归 μA∣B\mu_{\mathcal{A}|\mathcal{B}}μA∣B​，经 CNN 解码器得到粗尺度全局球面匹配 S^coarse\hat{\mathbf{S}}^{\text{coarse}}S^coarse 和粗置信度 c^coarse\hat{c}^{\text{coarse}}c^coarse。
  • 第四步：测地流多尺度逐级精修
    从粗尺度出发，一路经过 stride 16 → 8 → 4 → 2 → 1 的逐级上采样与精修循环（每一级严格执行 π → 2D 双线性采样与局部相关 → Refiner 预测残差并相加 → π⁻¹ 回到单位球面），最终拿到全分辨率的单位球面对应场 S^A→B\hat{\mathbf{S}}_{\mathcal{A}\to\mathcal{B}}S^A→B​（[1, 3, 320, 640]，共 204,800204,800204,800 个像素射线）以及全分辨率置信度图 c^A→B\hat{c}_{\mathcal{A}\to\mathcal{B}}c^A→B​（[1, 1, 320, 640]）。
  • 第五步：置信度过滤与全景均匀随机采样（非常关键的细节！）
    全图有 20 多万对稠密匹配，不可能全塞进 RANSAC / 8 点算法里，必须先抽样。

    注意：这里 EDM 专门推翻了 DKM 原版的采样策略！
    DKM 在透视图上用的是基于核密度估计（KDE）的平衡采样（balanced sampling），但 EDM 作者在 Section 5.1 明确指出：KDE 采样在全景图上容易把匹配点扎堆集中在高概率局部区域里，反而让球面其他方位空荡荡的——而对于 360° 相机位姿估计来说，匹配点必须尽量均匀铺满整个球面才能把旋转和平移约束稳！
    因此，EDM 的推理后处理非常简单直接：

    1. 先按 置信度阈值 0.8 筛掉不可靠和被遮挡的像素（只留 c^A→B>0.8\hat{c}_{\mathcal{A}\to\mathcal{B}} > 0.8c^A→B​>0.8 的高质量匹配）；
    2. 从筛完的可靠匹配里随机均匀采样最多 5,000 对，确保对应关系覆盖整个 360° 球面。
  • 第六步：球面相对位姿估计或稠密三角化
    把这至多 5,000 对单位球射线 (SA,i,  S^B,i)(\mathbf{S}_{\mathcal{A}, i},\; \hat{\mathbf{S}}_{\mathcal{B}, i})(SA,i​,S^B,i​) 送进 Solarte et al.（Robust 360-8PA，ICRA 2021） 提出的球面归一化 8 点算法 + 非线性优化，直接解出本质矩阵 EEE 与两视图相对位姿 (R,t)(R, t)(R,t)。如果下游要做三维重建，则进一步用算出来的相对位姿对所有高置信度稠密射线做球面三角化（spherical triangulation），就像论文 Figure 11 展示的那样，直接生成连大白墙都能填满的稠密 3D 点云。

4.2 时间与显存复杂度分析

原论文正文没有给出具体的单对推理毫秒数（FPS）和峰值显存数字（这一点我们实事求是标明：原文未披露具体推理速度与显存实测值），不过我们完全可以从算法结构上把它的计算复杂度算得一清二楚：

  1. SSAM 粗尺度 GP 回归的复杂度：

    每一级精修主要开销在局部相关计算 Corr⁡Ωkl\operatorname{Corr}_{\Omega_k}^lCorrΩk​l​ 与卷积 Refiner，复杂度为 O(HlWlKCl)O(H_l W_l K C_l)O(Hl​Wl​KCl​)，与像素数成线性关系。双向坐标变换 π\piπ 和 π−1\pi^{-1}π−1 纯粹是逐像素的 sin / cos / atan2 / asin 基本运算，没有任何可学习参数，几乎不占显存也不拖慢速度。
  3. 对比 Cubemap 方案的巨大效率优势：
    如果把一张 ERP 拆成 6 张透视图（Cubemap）再拿透视稠密匹配器去两两匹配，在未知相对朝向的情况下最多要做 6×6=366 \times 6 = 366×6=36 对透视推理；而 EDM 只需对一对 ERP 图像跑 1 次端到端前向推理，既省下了成倍的推理开销，又完整保留了跨整个 360° 视野的全局相关性。

5.1 评测协议与指标口径

  • 评测数据集：
    • Matterport3D 测试集：18 个未见过的室内场景，重叠率 >30%> 30\%>30%，共 4,575 对全景图（640×320640 \times 320640×320）；
    • Stanford2D3D 测试集（纯零样本泛化！）：来自 3 栋建筑的 6 个大型室内空间，共 1,413 张全景图，筛选重叠率 >50%> 50\%>50% 的 3,460 对图像（640×320640 \times 320640×320）。注意：EDM 完全没有在 Stanford2D3D 上微调过，直接拿 Matterport3D 训好的权重零样本上去测！ 而且 Stanford2D3D 全景图上下两极存在大片缺失黑洞（missing regions），非常考验模型的空间鲁棒性；

  • 统一位姿求解器与核心指标：
    • 所有方法匹配出的对应点，全部统一喂给 Solarte et al.（Robust 360-8PA） 估计两视图相对位姿；
    • 指标为经典的相对位姿误差曲线下面积 AUC@5°、AUC@10°、AUC@20°（数值越高越好，最高 100；@5° 最严苛，要求旋转和平移误差都在 5∘5^\circ5∘ 以内才拿高分）。

6. 优缺点、适用场景与局限边界

看完了耀眼的成绩单，我们冷静下来，结合原论文 Section 6 坦承的局限以及实际工程落地的视角，把 EDM 的强项、短板和适用边界梳理清楚。

主要优点

  1. 单次前向覆盖 360° 全局视野：彻底告别 Cubemap 拆 6 张图反复推理的臃肿流程，在单张 ERP 上直接利用全局上下文完成稠密对齐，对室内大面积白墙、地板、重复家具等弱纹理场景格外友好。
  2. 几何表达极其干净且无痛跨接缝：3D 单位球位置嵌入 + π ↔ π⁻¹ 双向测地流精修 + 单位球余弦角损失 三位一体，不用魔改昂贵的球面卷积核（Spherical CNN），只靠标准 2D CNN 算子就原生获得了极点畸变感知和左右 ±π\pm\pi±π 边界无缝连续性。
  3. 跨数据集零样本泛化扎实：仅在 61 个室内场景（Matterport3D）上训了 2 天（单卡 RTX 3090），直接零样本迁移到带极区黑洞的 Stanford2D3D 上 AUC@20° 达到 82.72，在 EgoNeRF 与 OmniPhotos 上也能给出视觉上很干净的稠密对齐与重建效果。

局限维度 具体表现与成因
强依赖“重力竖直对齐”先验 训练集 Matterport3D 几乎全是相机竖直摆放的室内扫描，且数据增强只做了水平方位角旋转。原论文 Section 6 明确指出：面对极端倾斜（大滚转 roll / 大俯仰 pitch）或剧烈翻滚的手持全景拍摄时，EDM 的匹配精度会明显下滑。
室外大场景泛化尚不充分 训练集完全来自室内环境，缺少室外开阔天空、远景建筑物、剧烈光照变化和动态行车等分布，直接部署到室外自动驾驶/街景全景图上存在域偏移风险。
高分辨率下的 GP 算力瓶颈 粗尺度高斯过程回归需要做 O((HcWc)3)O((H_c W_c)^3)O((Hc​Wc​)3) 矩阵求逆，原论文在 640×320640 \times 320640×320 下运行轻松，但如果业务需要直接输入 2K/4K 高清全景图而不加大粗尺度步长，显存和计算耗时都会急剧膨胀。
缺乏官方速度/显存基准与完整 3D 重建闭环 论文主实验聚焦在两视图相对位姿估计和双视图三角化，尚未集成进大规模多视图 360° SfM 或实时全景 SLAM 系统中做端到端帧率与轨迹误差评测。

适用场景建议

  • 非常推荐直接使用：室内机器人定位与建图、VR 看房 / 室内三维扫描配准、三脚架或云台水平采集的 360° 全景图两视图位姿估计与稠密点云三角化，尤其是**弱纹理、重复结构多、视角跨度较大（重叠率 40%～70%）**的室内场景。
  • 需要谨慎或先微调再上：手持自拍杆大角度歪斜拍摄、无人机航拍 360° 全景（大俯仰/滚转）、室外强光照/动态车流街景，以及对高分辨率 4K 实时推理有硬性要求的边缘端任务——遇到这些场景，建议补充全 3D 旋转增强（含 pitch/roll 扰动）与室外全景数据进行微调，并合理控制送入 SSAM 的粗尺度网格大小。

7. 总结

回顾整篇 EDM（CVPR 2025），它之所以能在全景匹配赛道上一次性拉出 26～42 个点的 AUC@5° 断层优势，靠的不是堆叠超大参数量，而是对球面相机几何本质的精准把握。我们可以把全篇精读浓缩成 4 条最核心的收获：

  1. 换对坐标系，问题解决一半：ERP 图像最棘手的“极点严重拉伸”和“左右 ±π\pm\pi±π 边界断裂”，在 2D 平面里是顽疾，但只要通过 π−1\pi^{-1}π−1 映射到 3D 单位球笛卡尔坐标，这两个痛点在几何上瞬间自动消失。
  2. 流形上的精修可以“借道 2D，落脚 3D”：测地流精修的 π → 2D Refiner 线性加残差 → π⁻¹ 双向变换非常值得借鉴——它保留了标准 2D 卷积、双线性插值与局部相关计算的工程高效性，又通过每次更新后反投影回单位球面，把流形约束与 360∘360^\circ360∘ 无缝跨界做得滴水不漏。
  3. 数据增强必须和几何表征相辅相成：随机方位角旋转增强（同步旋转 I,D,TI, D, TI,D,T）既无黑边损耗又零推理成本；更妙的是，它和 3D 球面位置嵌入产生了强烈的“1+1 > 2”协同效应，单独或联合都贡献了两位数的 AUC@5° 增益。
  4. 面向全景的损失与采样要彻底摆脱透视惯性：训练时放弃 2D 欧氏距离改用单位球面余弦角损失，推理时放弃容易扎堆的 KDE 平衡采样改用 certainty > 0.8 后的全局均匀随机采样，每一个看似不起眼的改动都在默默服务于同一个目标——让匹配真正长在 360° 的球面上。
