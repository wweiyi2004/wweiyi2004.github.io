走到这里，我们已经见识了两种输出形式：

  • 稀疏匹配（专题二）：输出几百到几千对离散角点；
  • 半稠密匹配（专题四）：输出 1/8 粗网格上筛出来的几千对亚像素匹配。

稠密特征匹配（Dense Feature Matching）则彻底不挑点了——它给图像 AAA 里的每一个像素 xA∈[−1,1]2x^A \in [-1, 1]^2xA∈[−1,1]2，都直接预测两样东西：

  2. 稠密置信度图（Certainty Map）pA→B∈[0,1]H×Wp^{A \to B} \in [0, 1]^{H \times W}pA→B∈[0,1]H×W：老老实实交代“这个像素到底在图 BBB 里看没看到、我这步预测有多靠谱”（遮挡区、天空、出界区的置信度接近 0）。

1. RoMa：视觉大模型加持的稠密匹配天花板

论文：RoMa: Robust Dense Feature Matching（CVPR 2024）

RoMa 来自稠密匹配代表作 DKM（CVPR 2023）的同一批作者。它没有搞玄学堆层，而是把稠密匹配里的特征表示、粗匹配歧义、细精修损失和下游采样四个老大难问题一个个拆开，全部给出了教科书级的解法。

1.2 深度拆解 RoMa 的 5 个关键设计

设计一：彻底解耦“粗语义特征”与“细定位特征”

作者做了一个非常犀利的消融观察：

  • DINOv2 在上亿张图上自监督预训练过，哪怕白天配黑夜、雕塑正拍配背拍，它依然能稳稳认出对应语义——但因为它把图切成 14×14 的粗块，边缘定位本来就很糙；而且如果你放开 DINOv2 权重跟着匹配数据微调，它反而会过拟合到 MegaDepth 里的欧洲教堂，丢掉通用泛化力！
  • VGG19 恰恰相反，语义泛化不如大模型，但浅层 1/2、1/1 卷积对像素边缘定位准到可怕。

所以 RoMa 干脆定死规矩：DINOv2 权重全程冻结，只喂给粗匹配阶段；细精修阶段完全不用 DINOv2，只吃专训的 VGG19 细特征！ 两套特征互不干扰、各司其职。

设计二：粗匹配解码器——为什么用“分类转回归”代替 L2 直接回归？

在 40×40 粗网格上，面对一排长得一模一样的拱门，图 AAA 的某个拱门在图 BBB 里可能同时在位置 x1=−0.6x_1 = -0.6x1​=−0.6（概率 0.5）和位置 x2=+0.6x_2 = +0.6x2​=+0.6（概率 0.5）都有极高相似度（多模态分布）。

看看两种建模方式的下场：

  • 直接 L2 回归：为了最小化平方误差期望，网络会输出两者的均值 x^=0.5(−0.6)+0.5(+0.6)=0.0\hat{x} = 0.5(-0.6) + 0.5(+0.6) = 0.0x^=0.5(−0.6)+0.5(+0.6)=0.0——直接指到两个拱门中间的空墙上，两个都不对！
  • RoMa 的分类转回归（Regression-by-Classification）：
    1. 先把目标图像归一化平面 [−1,1]2[-1, 1]^2[−1,1]2 均匀离散化成 KKK 个二维锚点类（如 64×6464 \times 6464×64 锚点格，论文用 Transformer Decoder 结合多尺度相关嵌入来预测这 KKK 类的概率分布 πk\pi_kπk​）；
    2. 训练时用**交叉熵分类损失（Cross-Entropy）**监督真实锚点类别（允许分布同时在多个拱门保持各自清晰的峰，绝不强行取平均！）；
    3. 推理时先找到概率最高的那个峰值锚点 k∗k^*k∗，只在它周围极小局部邻域里做软加权平均解出粗坐标 WcW_cWc​！

设计三：为什么用 Transformer 匹配解码器（而不只靠 DKM 的高斯过程）？

在老版 DKM 里，粗匹配主要靠无参数的高斯过程核回归（Gaussian Process）算出平滑粗特征；但高斯过程本身是局部平滑倾向的，遇到极端多模态或大遮挡时表现力受限。RoMa 在把两张图特征算完相似度/高斯过程嵌入后，再喂进一个 5 层 Transformer Decoder（不含位置编码，专门防止死记硬背图像绝对坐标） 来做全局非线性推理，直接输出上述锚点分类 logits 和粗置信度，鲁棒性再上一个大台阶。

设计四：细精修阶段用“鲁棒回归损失”，拒绝普通 L2！

在多尺度 ConvNet 精修阶段（1/8 → 1/4 → 1/2 → 1/1），绝大多数像素的粗 Warp 已经落在了真值周围几个像素以内，但总有少数困难像素在粗阶段就指偏了几十个像素。

如果用普通 L2 损失 ∥W−Wgt∥22\|W - W_{\mathrm{gt}}\|_2^2∥W−Wgt​∥22​：那少数误差 50 像素的离群点产生的平方梯度，会比误差 0.5 像素的正常点大 100 倍，直接把精修卷积核的权重扯歪！

RoMa 在精修阶段全部换用了广义 Charbonnier 鲁棒损失（对小误差像 L2 一样精细打磨亚像素，对大误差则压制梯度增长）：

Lfine=∑xcgt(x)(∥W(x)−Wgt(x)∥22+ε2)α/2,α∈(0,1)（如 α=0.5）L_{\mathrm{fine}} = \sum_{x} c_{\mathrm{gt}}(x) \left( \big\| W(x) - W_{\mathrm{gt}}(x) \big\|_2^2 + \varepsilon^2 \right)^{\alpha / 2}, \qquad \alpha \in (0, 1) \text{（如 } \alpha = 0.5 \text{）} Lfine​=x∑​cgt​(x)(​W(x)−Wgt​(x)​22​+ε2)α/2,α∈(0,1)（如 α=0.5）

（其中 cgt(x)∈{0,1}c_{\mathrm{gt}}(x) \in \{0, 1\}cgt​(x)∈{0,1} 是像素 xxx 在图 BBB 里确实可见的真值掩码；同时用二元交叉熵 LcertL_{\mathrm{cert}}Lcert​ 监督置信度图 p(x)p(x)p(x) 去逼近“该像素是否可见且匹配准确”。）

设计五：推理下游的“KDE 均衡采样（Balanced Sampling）”

拿到 560×560（超过 30 万像素）的稠密 Warp 和置信度图后，如果直接挑置信度最高的 5000 个点丢给 RANSAC 估本质矩阵，往往这 5000 个点全扎堆在画面正中一块纹理最清晰的路牌上——几何退化严重，算出来的相机位姿极不稳定！

RoMa 的采样技巧非常实用：先在置信度过阈值的候选点上做一次快速 核密度估计（KDE） 统计每个点周围有多拥挤，然后按“置信度 ÷ 局部空间密度”的概率去重采样！这样抽出来的 5000 对点既靠谱，又均匀铺满整张图像的各个角落，RANSAC 位姿精度立竿见影地提升。

2. 全景 EDM：把稠密匹配原生搬到 360∘360^\circ360∘ 单位球面上

论文：EDM: Equirectangular Projection-Oriented Dense Kernelized Feature Matching（CVPR 2025，NAVER LABS & 马里兰大学）

2.1 一看公式就明白：为什么 ERP 全景图会把普通匹配器干碎？

360∘360^\circ360∘ 全景相机拍出来的最常见格式是 ERP（Equirectangular Projection，等距柱状投影），分辨率通常是 H×WH \times WH×W（宽高比 1:2）。

ERP 像素坐标 (u,v)(u, v)(u,v) 到球面经纬度 (ϕ,θ)(\phi, \theta)(ϕ,θ) 再到单位球面 3D 笛卡尔坐标 s=(x,y,z)⊤\mathbf{s} = (x, y, z)^\tops=(x,y,z)⊤ 的精确映射关系是：

ϕ=(uW−12)⋅2π∈[−π,π],θ=(12−vH)⋅π∈[−π2,π2]\phi = \left(\frac{u}{W} - \frac{1}{2}\right) \cdot 2\pi \in [-\pi, \pi], \qquad \theta = \left(\frac{1}{2} - \frac{v}{H}\right) \cdot \pi \in \left[-\frac{\pi}{2}, \frac{\pi}{2}\right] ϕ=(Wu​−21​)⋅2π∈[−π,π],θ=(21​−Hv​)⋅π∈[−2π​,2π​]

s=(xyz)=(cos⁡θsin⁡ϕsin⁡θcos⁡θcos⁡ϕ),∥s∥2=1\mathbf{s} = \begin{pmatrix} x \\ y \\ z \end{pmatrix} = \begin{pmatrix} \cos\theta \sin\phi \\ \sin\theta \\ \cos\theta \cos\phi \end{pmatrix}, \qquad \|\mathbf{s}\|_2 = 1 s=​xyz​​=​cosθsinϕsinθcosθcosϕ​​,∥s∥2​=1

盯着上面公式里的 cos⁡θ\cos\thetacosθ 和 ϕ\phiϕ，立刻就能看穿普通 2D 透视匹配器（如 DKM、LoFTR、RoMa）直接跑 ERP 全景图时的两大死穴：

  1. 两极疯狂拉伸（cos⁡θ→0\cos\theta \to 0cosθ→0）：当靠近天花板或地板（θ→±π2\theta \to \pm \frac{\pi}{2}θ→±2π​）时，cos⁡θ\cos\thetacosθ 趋近于 0，球面上真实相距只有 1 厘米的两个点，在 ERP 平面上横向像素距离 Δu\Delta uΔu 会被拉长几十倍！用 2D 平面坐标去算位置编码和回归偏移量 (Δu,Δv)(\Delta u, \Delta v)(Δu,Δv)，在极点附近彻底失控；
  2. 左右接缝强行撕裂（ϕ=−π\phi = -\piϕ=−π 与 ϕ=+π\phi = +\piϕ=+π）：在真实球面上，图像最左边 u=0u=0u=0 和最右边 u=W−1u=W-1u=W−1 根本就是挨在一起的邻居，但在 2D 矩形上被硬生生切到了天涯海角！

以前为了绕过这个问题，大家把全景图切成 6 张透视立方体贴图（Cubemap）两两配对——不仅要跑 6×6=366\times 6 = 366×6=36 次前向推理慢到崩溃，还把 360∘360^\circ360∘ 完整的全局几何上下文切成了碎片。

2.2 一步步看全景 EDM 的球面原生架构

全景 EDM 建立在核化稠密匹配（DKM）范式之上，但从头到尾把“2D 平面坐标”彻底替换成了单位球面几何：

text
两张 360° ERP 全景图 I_A, I_B [3, H, W]
        │
        ▼  第一步：特征提取 + 球面 3D 位置编码（Spherical Positional Embeddings）
           不再把 2D 网格 (u, v) 做位置编码，
           而是把每个网格先投影成单位球面 3D 笛卡尔坐标 s = (x, y, z)，直接对 3D 球面坐标编码！
           （这样最左列和最右列的编码自然连续，两极拉伸也被真实球面距离自动校正！）
        │
        ▼  第二步：球面核化粗匹配（Spherical Dense Kernelized Matching）
           直接预测图 A 球面点 s^A 对应到图 B 单位球面上的粗方向向量 ŝ^B ∈ S²（及置信度）
           ──▶ 一次前向完整保留 360° 全景全局视野，彻底告别 Cubemap 切图！
        │
        ▼  第三步：双向坐标转换 + 测地线流精修（Geodesic Flow Refinement）
           ┌──────────────────────────────────────────────────────────────┐
           │ 每一级精修尺度：                                               │

           │  ② 在单位球面上预测测地线残差偏移（沿球面大圆弧/切空间更新），      │
           │     而不是在扭曲的 ERP 平面上直接加 (Δu, Δv)！                   │
           │  ③ 在球面角坐标 (θ, φ) 与 3D 笛卡尔坐标 (x, y, z) 之间双向转换， │
           │     逐级收敛到高精度球面稠密对应场！                              │
           └──────────────────────────────────────────────────────────────┘
        │
        ▼
输出：球面稠密对应场 + 置信度图（可直接送进球面 8 点法 / 5 点法 RANSAC 算 360° 相机相对位姿！）

重点体会“测地线流精修（Geodesic Flow Refinement）”有多关键：

  • 在 ERP 平面上，赤道移动 5 像素对应转动 2∘2^\circ2∘，但在接近北极的天花板上移动 5 像素可能只转动了 0.05∘0.05^\circ0.05∘——一个卷积核根本没法用同一套偏移尺度同时伺候赤道和两极；
  • 搬到单位球面上做测地线流更新后，无论像素在赤道还是两极，单位步长对应的都是完全一致的真实三维球面夹角！

结果极其惊人：在 Matterport3D 和 Stanford2D3D 两个主流室内 360∘360^\circ360∘ 全景数据集上，全景 EDM 相比适配后的透视稠密匹配器，AUC@5° 直接暴涨了 +26.72 和 +42.62 个百分点，一举确立了全景原生稠密匹配的新标杆。

3. 总结：稠密匹配什么时候该上场？

  • 透视图的极端困难场景（大视角、昼夜/跨季、弱纹理）+ 允许用独立 GPU 换极致精度：直接上 RoMa。它的核心精髓非常值得跨任务复用——“冻结基础大模型抓语义 + 专用小 CNN 抓定位 + 分类转回归解歧义 + 鲁棒损失防离群点 + KDE 均衡采样稳 RANSAC”；
  • 360∘360^\circ360∘ 全景相机（全景 SLAM、街景采集、室内 3D 漫游重建）：记住 ERP 两极拉伸和左右接缝两大畸变本质，优先看 全景 EDM 这种原生单位球面编码 + 测地线流精修路线，不要再硬套透视匹配器或暴力拆 36 对 Cubemap。

前五个专题我们把 2D-2D 图像匹配的四大流派（稀疏提取、稀疏匹配、误匹配剔除、半稠密、稠密）全部走透了。最后一篇 专题（六）：无描述子 2D-3D 匹配与视觉重定位，我们跨向三维地图定位——看看连视觉描述子都彻底扔掉后，DGC-GNN 和 A2-GNN 怎么靠纯几何排布和极轻量颜色线索算出相机的 6-DoF 位姿！
