在上一篇 【学习笔记】SuperPoint 里，我们已经把深度学习局部特征提取的基本骨架走了一遍：输入一张图，经过共享 CNN 编码器，分出检测头（找点）和描述头（给点算 256 维向量）。

SuperPoint 跑通了整个范式，但只要你真的拿它去训模型或者部署到项目里，马上就会撞上四堵墙：

  1. 训练数据墙：SuperPoint 靠随机“单应变换”自己造图像对，但真实世界是三维的，有遮挡、有视差，单应矩阵模拟不出来。如果改用真实多视角照片来训描述子，难道必须先花大价钱跑出稠密深度图才能标像素对应真值吗？ → CAPS 证明了：只给相机相对位姿（极线约束），连深度图都不要，照样能训出强描述子！
  2. 检测不可微墙：SuperPoint 把 8×8 小块当 65 分类来训，坐标天然卡在整数像素上，而且 argmax + NMS 不可微，没法把定位误差直接反向传回检测头。 → ALIKE 提出了可微关键点检测（DKD），让网络端到端回归亚像素坐标，同时大幅轻量化。
  3. 稠密描述算力浪费墙：一张 480×640 的图有 30 万个像素，最后其实只挑 500～1000 个关键点。像 ALIKE 那样先算出整张原图大小的稠密描述图，再按关键点去采样，99% 的算力全白烧了；而且固定正方形网格采样在遇到旋转、透视形变时非常死板。 → ALIKED 提出了稀疏可变形描述头（SDDH），只在选出来的关键点上动态变形采样。
  4. 端侧 CPU 实时墙：即便轻量如 ALIKED，放在没有独立 GPU 的无人机、手机 CPU 上跑高分辨率图依然很吃力；而且纯稀疏方法一遇到白墙、弱纹理就容易点数断档。 → XFeat 重新算了一遍 CNN 的 FLOPs 账单，把浅层通道压到极致，做出只有 64 维的紧凑描述子，在 CPU 上都能实时跑，还附带了轻量 MLP 半稠密精修模式。

1. CAPS：只给相机位姿，怎么靠一条“极线”训出强描述子？

论文：Learning Feature Descriptors using Camera Pose Supervision（ECCV 2020）

在开始之前先给 CAPS 定个位：CAPS 只做描述子，不管找点。 推理时你可以拿 SIFT、SuperPoint 或任何检测器找出来的点，去 CAPS 输出的特征图里插值取描述子。

1.1 为什么“只知道相机位姿”也能监督？

假设我们有两张从不同角度拍同一栋建筑的照片 I1,I2I_1, I_2I1​,I2​，并且通过常规 SfM 拿到了两张照片之间的相机内参和相对位姿——也就是已知基础矩阵（Fundamental Matrix）F∈R3×3F \in \mathbb{R}^{3\times 3}F∈R3×3（注意：不需要稠密深度图，也不需要知道图 1 某个像素严格落在图 2 哪个像素！）。

立体几何里有一条铁律：对于图 1 里的任意一个查询点 x1=(u1,v1,1)⊤x_1 = (u_1, v_1, 1)^\topx1​=(u1​,v1​,1)⊤（齐次坐标），它在图 2 里真正的对应点 x2x_2x2​ 虽然位置未知，但一定落在图 2 的一条直线——极线（Epipolar Line）上：

l2=Fx1=(a,b,c)⊤⟹au2+bv2+c=0l_2 = F x_1 = (a, b, c)^\top \quad \Longrightarrow \quad a u_2 + b v_2 + c = 0 l2​=Fx1​=(a,b,c)⊤⟹au2​+bv2​+c=0

CAPS 的核心想法就是：让网络自己去图 2 里“软查找” x1x_1x1​ 的对应位置 x^2\hat{x}_2x^2​，然后拿尺子量一下 x^2\hat{x}_2x^2​ 离极线 l2l_2l2​ 有多远——越远扣分越多！

1.2 网络结构与“粗到细”可微软匹配流程

先看整体数据流（假设输入两张 H×WH \times WH×W 的 RGB 图像，以 480×640 为例）：

注意：两张特征图（粗 128 维 + 细 128 维）在通道维拼起来就是最终的 256 维描述子（粗层抓全局语义，细层抓局部精准边缘）。

接下来进入训练时最核心的两阶段可微软匹配（拿图 1 里的一个采样点 x1x_1x1​ 为例）：

第一步：粗尺度全图软匹配（锁定大方向）

  1. 从 F1cF_1^cF1c​ 里按 x1x_1x1​ 位置双线性插值取出 128 维查询向量 f1c(x1)\mathbf{f}_1^c(x_1)f1c​(x1​)；
  2. 拿它和图 2 粗描述图 F2cF_2^cF2c​ 里的所有 30×40=120030 \times 40 = 120030×40=1200 个网格向量逐个算内积（相关性图 McM_cMc​）；
  3. 对整张相关性图做二维 Softmax，得到每个位置是对应点的概率分布 pc(x∣x1)p_c(x \mid x_1)pc​(x∣x1​)；
  4. 用这个概率分布对图 2 所有坐标做加权平均，算出可微的期望对应坐标 x^2c\hat{x}_2^cx^2c​：

x^2c=∑x∈I2cx⋅pc(x∣x1,I1,I2)\hat{x}_2^c = \sum_{x \in I_2^c} x \cdot p_c(x \mid x_1, I_1, I_2) x^2c​=x∈I2c​∑​x⋅pc​(x∣x1​,I1​,I2​)

（为什么要做加权平均而不是 argmax？ 因为 argmax 不可微，梯度传不回去！换成 Softmax 期望后，坐标 x^2c\hat{x}_2^cx^2c​ 对描述子特征完全可微。）

第二步：细尺度局部窗口软匹配（拉高定位精度）
如果直接在 1/4 细图（120×160 = 19200 个像素）上做全图相关性，显存会直接炸掉。于是 CAPS 顺着刚才算出来的粗位置 x^2c\hat{x}_2^cx^2c​，在细图 F2fF_2^fF2f​ 上只切出一个局部小窗口 W\mathcal{W}W（例如半径对应粗图几个格子），只在小窗口内部再做一次一模一样的 Softmax 期望，算出精细对应位置 x^2f\hat{x}_2^fx^2f​！

1.3 训练损失：三条规则把描述子“逼上正轨”

拿到可微预测坐标 x^2\hat{x}_2x^2​（粗、细两层各自算一遍）之后，怎么防止网络钻空子？CAPS 用了极线损失 + 循环一致损失 + 不确定度加权三板斧：

第一板斧：极线损失（Epipolar Loss）

算预测点 x^2\hat{x}_2x^2​ 到真实极线 l2=Fx1=(a,b,c)⊤l_2 = F x_1 = (a, b, c)^\topl2​=Fx1​=(a,b,c)⊤ 的点到直线垂直距离：

Lep(x1)=∣x^2⊤(Fx1)∣a2+b2L_{\mathrm{ep}}(x_1) = \frac{\big|\hat{x}_2^\top (F x_1)\big|}{\sqrt{a^2 + b^2}} Lep​(x1​)=a2+b2​​x^2⊤​(Fx1​)​​

第二板斧：循环一致损失（Cycle Consistency Loss）——堵死“沿极线乱滑”的漏洞！

光有极线损失有个致命漏洞：只要 x^2\hat{x}_2x^2​ 沿着极线 l2l_2l2​ 随便乱跑，点到直线的距离永远是 0！网络完全可以把图 1 的所有点都胡乱指到极线上的同一个位置。

CAPS 的堵漏办法极其聪明：既然你能从 x1x_1x1​ 软匹配到 x^2\hat{x}_2x^2​，那我就拿 x^2\hat{x}_2x^2​ 处的描述子再反向去图 1 里软匹配一次，算出回跳坐标 x^1\hat{x}_1x^1​！ 如果你真的是找对了对应点，回跳一定得落回原来的 x1x_1x1​ 附近：

Lcycle(x1)=∥x^1−x1∥2L_{\mathrm{cycle}}(x_1) = \|\hat{x}_1 - x_1\|_2 Lcycle​(x1​)=∥x^1​−x1​∥2​

第三板斧：方差倒数加权（自动屏蔽弱纹理与遮挡点）

真实照片里总有天空白墙或者被遮挡的点，它们在图 2 里根本没有唯一对应，硬逼着它们凑极线只会产生脏梯度。CAPS 顺手算了一下匹配概率分布 p(x∣x1)p(x \mid x_1)p(x∣x1​) 的空间总方差 σ2(x1)\sigma^2(x_1)σ2(x1​)：

  • 如果概率分布集中在一个尖峰上 → σ\sigmaσ 很小 → 说明这个点很确定 → 给高权重；
  • 如果概率分布糊在整张图上 → σ\sigmaσ 很大 → 说明是弱纹理或遮挡点 → 自动降权！

总损失写成：

L=∑x11σ(x1)(Lep(x1)+λ Lcycle(x1))L = \sum_{x_1} \frac{1}{\sigma(x_1)} \Big( L_{\mathrm{ep}}(x_1) + \lambda \, L_{\mathrm{cycle}}(x_1) \Big) L=x1​∑​σ(x1​)1​(Lep​(x1​)+λLcycle​(x1​))

1.4 推理时怎么用？（注意和训练的区别！）

注意：上面那一长串极线、基础矩阵 FFF、粗细软匹配、反向循环，全都是训练时为了造监督信号才跑的！

真正推理时超级简单：

  1. 把单张 RGB 图输进 ResNet-50 + FPN，拿到粗特征图 FcF^cFc（128 维）和细特征图 FfF^fFf（128 维）；
  2. 用外部检测器（如 SIFT、SuperPoint）给出关键点坐标；
  3. 在 FcF^cFc 和 FfF^fFf 上分别双线性插值并做 L2 归一化，拼成一个 256 维描述子完事！

优缺点小结：

  • 优点：彻底摆脱了像素级深度真值依赖，用常规多视角位姿数据（如 MegaDepth）就能端到端训出跨视角极强的描述子；
  • 缺点：自己不带关键点检测器；主干用 ResNet-50 推理偏重，不适合端侧实时场景。

2. ALIKE：可微关键点检测（DKD）+ 轻量实时提取

论文：ALIKE: Accurate and Lightweight Keypoint Detection and Descriptor Extraction（TMM 2022）

SuperPoint 虽然能同时找点和算描述子，但它的检测头是按 8×8 格做 65 分类，既没法输出亚像素坐标，也没法把重投影坐标误差直接传回检测头。ALIKE 就是为了同时解决**“可微亚像素检测”和“轻量实时”**两个问题而生的。

2.1 网络结构与张量维度追踪

以 480×640 输入图像为例（以常见的 ALIKE-N 为例，通道配置 c1=16, c2=32, c3=64, c4=128，最终输出维度 dim=64）：

可以看到 ALIKE 的骨干设计非常克制：只有 4 个轻量卷积/残差块，把四层不同感受野的特征压缩通道后统一上采样到原图尺寸拼接，既保住了原图级定位精度，参数量又压到了只有几十万（SuperPoint 约 130 万，ALIKE-T 仅约 8 万，ALIKE-N 约 32 万！）。

2.2 核心杀手锏：DKD（可微关键点检测）怎么实现亚像素可微？

拿到了原图大小的分数图 S∈RH×WS \in \mathbb{R}^{H \times W}S∈RH×W 后，传统做法是做完 NMS 直接取像素整数坐标 (u, v)——这一步一取整，梯度就彻底断了。

ALIKE 的 DKD 模块把取点拆成了两步：

第一步（硬定位中心，不传梯度）：在分数图 SSS 上做标准局部极大值 NMS（窗口 N×NN \times NN×N，如 5×55\times 55×5）和阈值筛选，找到所有局部峰值的整数中心坐标 pnms=(u0,v0)\mathbf{p}_{\mathrm{nms}} = (u_0, v_0)pnms​=(u0​,v0​)。

第二步（软回归亚像素偏移，全程可微！）：以 pnms\mathbf{p}_{\mathrm{nms}}pnms​ 为中心，切出它周围的 N×NN \times NN×N 局部小窗口，把窗口内每个相对偏置 (i,j)∈{−⌊N/2⌋,…,⌊N/2⌋}2(i, j) \in \{-\lfloor N/2 \rfloor, \dots, \lfloor N/2 \rfloor\}^2(i,j)∈{−⌊N/2⌋,…,⌊N/2⌋}2 对应的分数拿出来做一次带温度系数 ttt 的 Softmax：

s′(i,j)=exp⁡(t⋅S(u0+i,v0+j))∑(m,n)exp⁡(t⋅S(u0+m,v0+n))s'(i, j) = \frac{\exp\big(t \cdot S(u_0 + i, v_0 + j)\big)}{\sum_{(m,n)} \exp\big(t \cdot S(u_0 + m, v_0 + n)\big)} s′(i,j)=∑(m,n)​exp(t⋅S(u0​+m,v0​+n))exp(t⋅S(u0​+i,v0​+j))​

然后对相对偏置做期望加权，算出连续的亚像素偏移量 Δp\Delta \mathbf{p}Δp：

Δp=∑(i,j)s′(i,j)⋅(i,j),p=pnms+Δp\Delta \mathbf{p} = \sum_{(i, j)} s'(i, j) \cdot (i, j), \qquad \mathbf{p} = \mathbf{p}_{\mathrm{nms}} + \Delta \mathbf{p} Δp=(i,j)∑​s′(i,j)⋅(i,j),p=pnms​+Δp

举个直观例子：假设 3×33\times 33×3 窗口里正中心分数是 0.8，右边一格分数是 0.7，左边一格是 0.1，那么 Softmax 加权算出来的 Δx\Delta xΔx 大约是 +0.3 像素——最终点会自动往右侧微移 0.3 像素，而且这个坐标 p\mathbf{p}p 是分数图 SSS 的光滑函数，重投影误差可以直接顺着 p\mathbf{p}p 反向传播去调分数图的形状！

2.3 四个训练损失各自管什么？

训练时使用带已知几何变换或深度+位姿对应关系的图像对 (IA,IB)(I_A, I_B)(IA​,IB​)，ALIKE 联合优化 4 个损失：

  1. 重投影损失 LrpL_{\mathrm{rp}}Lrp​（教网络“找点找得稳、找得准”）：
    把图 A 检出的亚像素点 pA\mathbf{p}_ApA​ 投影到图 B 得到理论真值位置 pA→B\mathbf{p}_{A \to B}pA→B​，在图 B 中找离它最近的检出点 pB\mathbf{p}_BpB​，直接最小化两者距离（两边对称算）：

    Lrp=12(∥pB−pA→B∥2+∥pA−pB→A∥2)L_{\mathrm{rp}} = \frac{1}{2} \Big( \|\mathbf{p}_B - \mathbf{p}_{A \to B}\|_2 + \|\mathbf{p}_A - \mathbf{p}_{B \to A}\|_2 \Big) Lrp​=21​(∥pB​−pA→B​∥2​+∥pA​−pB→A​∥2​)

  2. 峰值损失 LpkL_{\mathrm{pk}}Lpk​（防分数图偷懒变成一马平川）：
    如果整张分数图到处都是 0.5，亚像素偏移也能算出 0，那就没法挑出清晰角点了。峰值损失强迫每个局部窗口的中心分数尽量高、而窗口内平均分数尽量低，逼着分数图长出“尖锐的山峰”：

    Lpk=1−1∣P∣∑p∈P(S(p)−mean⁡q∈N(p)S(q))L_{\mathrm{pk}} = 1 - \frac{1}{|\mathcal{P}|}\sum_{\mathbf{p} \in \mathcal{P}} \Big( S(\mathbf{p}) - \operatorname{mean}_{q \in \mathcal{N}(\mathbf{p})} S(q) \Big) Lpk​=1−∣P∣1​p∈P∑​(S(p)−meanq∈N(p)​S(q))

  3. 描述子 NRE 损失（Neural Reprojection Error Loss）：
    传统对比损失只拉近正样本、推开最难负样本；ALIKE 引入了 NRE 损失——拿图 A 点 pA\mathbf{p}_ApA​ 的描述子去和图 B 所有位置的描述子算相似度并做 Softmax，得到一张“描述子匹配概率分布图”，然后要求这张分布图和“真值投影点 pA→B\mathbf{p}_{A \to B}pA→B​ 处的独热分布”交叉熵最小！
  4. 可靠性损失 LrelL_{\mathrm{rel}}Lrel​（让“好匹配的点”分数更高）：
    如果某个点在 NRE 里算出来的匹配概率非常集中且准（说明它描述子辨识度高），就鼓励检测头在那里给更高的分数 S(p)S(\mathbf{p})S(p)；反之在重复纹理/模糊区就压低检测分数。

3. ALIKED：稀疏可变形描述头（SDDH），又快又抗形变

论文：ALIKED: A Lighter Keypoint and Descriptor Extraction Network via Deformable Transformation（TIM 2023）

看懂了 ALIKE，再看它的亲弟弟 ALIKED 就非常爽快——因为主干思路和 DKD 检测模块基本继承了 ALIKE，最惊艳的改动全部集中在把稠密描述头换成了 SDDH（Sparse Deformable Descriptor Head，稀疏可变形描述头）。

3.1 为什么说 ALIKE 的稠密描述头有“两宗罪”？

回头看上一节 ALIKE 的结构图，你会发现最后一步有个大坑：

  • 第一宗罪（算力严重浪费）：为了在原图尺度插值取描述子，ALIKE 必须把四层特征全都上采样到 480×640 并做整图卷积，算出一张 [B, 64, 480, 640] 的巨型稠密描述图——然而最后只取了其中 500 个点（不到总像素的 0.2%），剩下 99.8% 的像素描述子全算了个寂寞！
  • 第二宗罪（采样网格太死板）：普通卷积和双线性插值只在固定朝向的正方形网格上采样，一旦目标发生视角倾斜、缩放或局部旋转，固定网格采出来的邻域早已错位。

3.2 一步步拆解 SDDH 的完整计算过程

ALIKED 的解决办法堪称教科书级的“先找点，再干活”：

把上面第 ②～④ 步写成公式，一眼就能看清它的优雅：

Δpi,m=Om(f(pi)),m=1,2,…,M\Delta \mathbf{p}_{i, m} = \mathcal{O}_m\big(\mathbf{f}(\mathbf{p}_i)\big), \qquad m = 1, 2, \dots, M Δpi,m​=Om​(f(pi​)),m=1,2,…,M

di=L2Norm⁡ ⁣(∑m=1MWm f(pi+Δpi,m))\mathbf{d}_i = \operatorname{L2Norm}\!\left( \sum_{m=1}^{M} W_m \, \mathbf{f}\big(\mathbf{p}_i + \Delta \mathbf{p}_{i, m}\big) \right) di​=L2Norm(m=1∑M​Wm​f(pi​+Δpi,m​))

（通常取 M=16M = 16M=16，也就是每个关键点在周围动态派出 16 个“可变形采样点”。）

注意这里为什么给每个支撑位置分配不同的权重矩阵 WmW_mWm​，而不是简单求和？
因为如果直接把 16 个点的特征相加，就丢掉了相对空间排布（左边点和右边点混为一谈）；用各自独立的 WmW_mWm​ 投影后再求和，既等价于一次只在稀疏点上执行的可变形卷积，又完整保留了局部空间结构信息！

3.3 ALIKED 家族规格与实测定位

ALIKED 提供了几个不同大小的版本（名字里的 T/N 代表编码器大小，数字 16/32 代表采样支撑点或特征规模）：

  • ALIKED-T16：极轻量版本（参数量不到 20 万），适合高帧率嵌入式/移动端；
  • ALIKED-N16 / N32：默认主力版本（约 60～90 万参数，128 维描述子），在 HPatches、MegaDepth 和 IMC（图像匹配挑战赛）上综合表现极强——“ALIKED + LightGlue”已经成为目前学术界和工业界最受欢迎的稀疏匹配黄金搭档之一。

4. XFeat：重新算清 FLOPs 账单，在 CPU 上也能实时跑！

论文：XFeat: Accelerated Features for Lightweight Image Matching（CVPR 2024）

4.1 为什么以前的轻量网络放到普通 CPU 上还是卡？

很多论文标榜自己“参数量很小”，但跑在树莓派、普通笔记本 CPU 上照样只有几 FPS。XFeat 作者上来就戳破了窗户纸：真正拖垮推理速度的往往不是总参数量，而是高分辨率浅层的 FLOPs！

看一眼标准卷积层的计算量公式：

FLOPs=Hi⋅Wi⋅Cin⋅Cout⋅k2\mathrm{FLOPs} = H_i \cdot W_i \cdot C_{\mathrm{in}} \cdot C_{\mathrm{out}} \cdot k^2 FLOPs=Hi​⋅Wi​⋅Cin​⋅Cout​⋅k2

举个直观的算术例子：

  • 在原图分辨率 480×640 这一层，H×W=307,200H \times W = 307,200H×W=307,200；如果你像普通网络那样放 32 个通道，光一层 3×3 卷积就要算 28 亿次乘加！
  • 而在 1/32 分辨率 15×20 这一层，H×WH \times WH×W 只有 300（缩小了 1024 倍），哪怕放 128 个通道，计算量也几乎可以忽略不计！

所以 XFeat 定下了整套架构的第一铁律：保住高输入分辨率（否则定位不准），但把浅层通道数砍到极致，深层再把通道迅速加厚！

4.2 完整网络架构与张量维度追踪

下面拿 480×640 输入图，完整追踪 XFeat 的两条并行支路：

注意这两个非常精妙的设计细节：

  1. 浅层通道递增方式：普通网络分辨率减半时通道翻 2 倍（32→64→128），XFeat 从 4 通道起步，每次下采样通道接近翻 3 倍（4→8→24→64→128），把绝大部分计算全挪到了低分辨率深层，在普通 CPU 上能做到比 SuperPoint / ALIKE 快 5 倍左右！
  2. 关键点分支彻底解耦：直接把原图切 8×8 块用 1×1 卷积预测 65 类热力图，既超快，又不会和描述子主干互相抢容量（这对后面的半稠密模式特别重要）。

4.3 XFeat 的四大训练损失（清晰分工）

训练时使用带真值像素对应的图像对 (I1,I2)(I_1, I_2)(I1​,I2​)（如 MegaDepth + 合成单应 COCO 混合数据），四个损失各司其职：

  1. 描述子双 Softmax 损失 LdsL_{\mathrm{ds}}Lds​：
    取出真值对应的 NNN 对 64 维描述子，算 N×NN \times NN×N 相似度矩阵 S=F1F2⊤S = F_1 F_2^\topS=F1​F2⊤​，沿行和列双向做交叉熵（Dual-Softmax NLL），逼着对角线真匹配得分最高；
  2. 可靠性损失 LrelL_{\mathrm{rel}}Lrel​：
    怎么知道某个粗网格靠不靠谱？直接拿上面 Dual-Softmax 算出来的最大匹配概率 Rˉ1,Rˉ2\bar{R}_1, \bar{R}_2Rˉ1​,Rˉ2​ 当监督信号（用 L1 损失监督可靠性图 RRR）——能轻松配对成功的区域可靠性就高，配不准的白墙可靠性就低！
  3. 关键点蒸馏损失 LkpL_{\mathrm{kp}}Lkp​：
    不费劲重头搞单应适应了，直接拿成熟的 ALIKE 检测器在真实图上跑出关键点当老师，把它们转成 8×8 网格的 65 类标签，用交叉熵监督关键点热力图 KKK；
  4. 精细偏移分类损失 LfineL_{\mathrm{fine}}Lfine​（专门训给半稠密模式 XFeat 用！）*：
    对于粗网格上配对成功的两个 64 维描述子 (f1,f2)(f_1, f_2)(f1​,f2​)，把它们拼成 128 维送进一个极轻的 Match Refinement MLP，把粗网格内部 8×8 的真实精细像素偏移当成 64 分类问题用交叉熵监督！

4.4 推理时的“双形态”：稀疏模式 XFeat vs 半稠密模式 XFeat*

XFeat 推理时特别灵活，可以根据算力和场景自由切换两种模式：

形态一：稀疏模式（XFeat，极致高速）

  1. 从关键点热力图 KKK 解码并结合可靠性图 RRR 筛出 Top-K 个稀疏关键点；
  2. 按关键点坐标从 64 维描述图 FFF 里双线性插值取出描述子；
  3. 做最简单的最近邻匹配（或接 LightGlue）即可——因为描述子只有 64 维，连最近邻距离矩阵乘法都比 256 维快 4 倍！

形态二：半稠密模式（XFeat，弱纹理也能扛）*

  1. 把图像按多尺度（如 2 个尺度）过主干，直接丢掉稀疏关键点分支；
  2. 在 1/8 粗网格上按可靠性图 RRR 挑出高置信度网格，直接拿 64 维描述子做互为最近邻（MNN）粗匹配；
  3. 把粗配成功的成对描述子 (f1,f2)(f_1, f_2)(f1​,f2​) 喂进轻量 Match Refinement MLP，直接预测出 8×8 小块内的精细偏移量，把坐标精修到像素级！

不用跑任何沉重的 Transformer，XFeat* 就在纯卷积 + 小 MLP 里实现了轻量半稠密匹配，精度能大幅逼近甚至在部分场景追平 LoFTR，速度却快出一个数量级！

5. 总结：五代局部特征提取器横向选型指南

把 SuperPoint 和本专题的四篇连成一条完整路线：

  1. 想搞懂基础范式与自监督流程：先吃透 SuperPoint（合成预训练 + 单应适应 + 联合训练）；
  2. 手头只有相机位姿没有深度图，想自己训描述子：学 CAPS 的“可微软匹配 + 极线距离 + 循环一致 + 方差加权”；
  3. 想端到端把关键点定位训到亚像素：掌握 ALIKE 的 DKD 局部 Softmax 期望技巧；
  4. 追求稀疏匹配的综合高精度与稳健泛化：直接上 ALIKED（SDDH 稀疏可变形采样，配 LightGlue 非常稳）；
  5. 无 GPU / 移动端 / 无人机 / 追求极致帧率，或想在轻量模型里兼顾弱纹理半稠密：首选 XFeat / XFeat*。

拿到稀疏关键点和描述子之后，下一步就是把两张图的点配起来。下一篇 专题（二）：稀疏特征匹配，我们拆解 SuperGlue → SGMNet → LightGlue 是怎么用图注意力彻底淘汰暴力最近邻的。
